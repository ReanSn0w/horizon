# Таймеры Horizon

Запусти `horizon agent timer --help` через `shell_exec`, чтобы проверить наличие
адаптера в текущем Horizon home. Если бинарник отсутствует, команда
`horizon manager plugins install agent:timer` устанавливает его из управляемого
источника. Для исполнения нужен установленный `horizon-daemon`, имя `timer` в
`plugins.daemon.adapters` и запущенный `horizon daemon start`. Установка
и валидация не запускают службу. Учитывай текущий список адаптеров при изменении
конфигурации и запускай или перезапускай службу только по запросу пользователя.

Один таймер — один файл `$HORIZON_HOME/timers/<timer-id>.md`. В ID разрешены
1–64 строчные ASCII-буквы, цифры, дефисы и подчёркивания, первый символ —
буква или цифра. Меняй существующий файл под тем же именем, чтобы сохранить
учёт срабатываний. `name` — отображаемое имя, `description` — краткое описание.
`workspace` — абсолютный путь к существующему каталогу. Markdown после
frontmatter — полноценное поручение. `enabled` можно опустить, тогда оно
считается равным `true`.

```markdown
---
name: Проверка отчётов
description: Найти новые локальные отчёты
workspace: /absolute/path/to/project
schedule:
  every: 30m
  timezone: Europe/Moscow
  windows:
    - start: "09:00"
      end: "21:00"
enabled: true
---

Найди новые файлы в reports/. Запиши имена обработанных файлов в
state/processed.json внутри workspace, чтобы следующий запуск мог их пропустить.
Сохрани итог в истории Horizon.
```

`every` — Go duration от `1m`, привязанный к сетке Unix epoch. Для запуска в
местное время замени `every` на `cron: "0 10 * * 1-5"` (по будням в 10:00).
Поля cron идут в порядке минута, час, день месяца, месяц, день недели. Можно
использовать списки, диапазоны, шаги и звёздочки. Воскресенье — 0 или 7. Если
оба поля дней ограничены, достаточно совпадения одного. Для обоих типов
расписания обязателен IANA timezone. Окна включают начало, исключают конец,
могут проходить через полночь и объединяются при пересечении. Без окон таймер
доступен круглосуточно.

Каждый запуск получает новую сессию в workspace. Храни состояние между
запусками в файле проекта, например журнал обработанных идентификаторов или
последнюю проверенную версию. Старые слоты после простоя пропускаются. У таймера
одна ожидающая или активная задача. Таймерные задачи одного workspace исполняются
по очереди. Ожидающая задача пропускается после закрытия окна, начавшийся ход
может завершиться позже. Для уведомления можно явно указать в поручении
использовать доступное отправляющее расширение, если оно установлено и включено.

Создавай и редактируй файл через `shell_exec`. Запиши целиком во временный файл
в том же каталоге под именем без окончания `.md`, проверь успешность записи и
опубликуй атомарной заменой `mv`. Для нового файла подойдёт шаблон:

```sh
set -eu
dir="$HORIZON_HOME/timers"
mkdir -p "$dir"
tmp=$(mktemp "$dir/.timer-XXXXXX")
trap 'rm -f "$tmp"' EXIT HUP INT TERM
cat >"$tmp" <<'TIMER'
---
name: Проверка отчётов
description: Найти новые локальные отчёты
workspace: /absolute/path/to/project
schedule:
  cron: "0 10 * * 1-5"
  timezone: Europe/Moscow
---
Найди новые файлы в reports/ и обнови state/processed.json в workspace.
TIMER
mv -f "$tmp" "$dir/check-reports.md"
horizon agent timer validate check-reports
```

Подставь реальный workspace и ID, сохрани действующее поручение при точечной
правке, выбирай уникальный маркер heredoc. Используй
`horizon agent timer validate` для всех файлов, в том числе отключённых.
Результаты исполнения и блокировки доступны через `horizon agent timer status`.
Если исход задачи неизвестен, разбери его по task ID и истории, прежде чем
вызвать `horizon agent timer unblock <timer-id>` по запросу пользователя.
