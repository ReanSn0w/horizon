# Создание навыков Horizon

Создай навык под задачу пользователя. Из промпта определи назначение, условия
применения, ожидаемый результат и ограничения. Уточняй только то, без чего
можно существенно ошибиться в результате; уже заданные требования не спрашивай
повторно. Не расширяй поручение на посторонние действия.

## Каталог назначения

Текущий навык загружается через `skill_read` с именем `skill-creator`.
Ответ инструмента содержит `base_dir` — абсолютный каталог этого навыка.
Его родительский каталог является каталогом навыков выбранного Horizon home.
Создавай новый навык в соседнем каталоге:
`<родитель base_dir>/<имя-навыка>/SKILL.md`.

Не подставляй `~/.horizon`: пользователь мог запустить Horizon с `--home`.
Имя каталога выбирай из строчных латинских букв, цифр и дефисов, без слешей,
`..` и абсолютных путей. Обычно имя каталога совпадает с YAML-полем `name`.

Перед записью проверь доступный каталог навыков и содержимое каталога назначения
через `dir_list` / `file_read`. Имя `name` должно быть уникальным среди всех
навыков, даже если их каталоги называются иначе. Если имя занято, выбери другое
свободное имя. Изменяй существующий навык только когда пользователь поручил
его обновление; сначала прочитай его содержимое и сохрани полезные инструкции.

## Содержимое

`SKILL.md` — UTF-8 Markdown с YAML frontmatter. Минимальная форма:

```markdown
---
name: review-go
description: Проверяет изменения Go-проекта и сообщает о найденных дефектах. Используй для запросов ревью Go-кода.
---

# Проверка Go-проекта

Прочитай инструкции проекта и изменения, относящиеся к запросу.
Проверь корректность изменённого поведения и обработку ошибок.
Выбери проверки, соответствующие затронутым пакетам и требованиям проекта.
Сообщи о подтверждённых дефектах с путями к файлам; укажи выполненные проверки
и ограничения проверки.
```

Адаптируй пример к запросу. В `description` кратко объясни, что делает навык
и когда его выбирать. В теле укажи конкретный порядок работы, необходимые
ограничения и способ проверки результата. Не заполняй инструкции общими
призывами к качеству. Не включай секреты, ключи или данные текущей сессии.

Для нового файла используй `file_create`: он создаёт отсутствующие родительские
каталоги и не перезаписывает существующий файл. Для изменения используй
`file_update` после чтения. `file_read` читает диапазон строк: продолжай чтение,
если файл не получен целиком. `shell_exec` доступен для необходимых команд;
учитывай его рабочий каталог и корректно экранируй пути.

Добавляй `scripts/`, `references/` или `assets/` только при конкретной пользе.
Ссылки на ресурсы задавай относительно каталога навыка и объясняй, когда их
читать или запускать. Не ссылайся на инструменты, плагины или служебные скрипты
других агентов, которых нет в Horizon. Пользовательские навыки исполняются
доступными инструментами Horizon; дополнительные зависимости опиши явно.

## Проверка и результат

После записи вызови через `shell_exec` команду
`horizon skills validate --id <ID>`. ID — имя каталога навыка, которое может
отличаться от YAML-поля `name`. Если ID содержит пробелы или специальные
символы, экранируй его для `/bin/sh`.

Исправь найденные ошибки формата и повтори проверку до успеха. Дополнительно
проверь содержательность инструкций и существование упомянутых ресурсов.
Если добавлены скрипты, выполни подходящую проверку в пределах задачи пользователя.

Для просмотра навыков используй `horizon skills list`. По поручению пользователя
отключай навык через `horizon skills disable --id <ID>` и включай через
`horizon skills enable --id <ID>`. Отключение добавляет ID в `disabled_skills`
конфигурации, включение удаляет его; файлы навыка сохраняются.

Сообщи путь созданного или изменённого навыка и пример запроса для применения.
Каталог фиксируется перед началом хода: новый навык и изменения активности
будут доступны со следующего запуска Horizon. `horizon skills validate` читает свежий
файл с диска, а повторный `skill_read` не обновляет текущий каталог.
