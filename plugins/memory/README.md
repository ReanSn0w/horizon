# Memory

Память агента, пользователя и workspace в локальных JSON-файлах. В ядре Horizon
нет логики памяти: плагин подключается общим протоколом расширений агента.

## Установка и включение

```sh
make install-memory
# Для другого home:
make install-memory HORIZON_HOME=/path/to/home
```

В существующий `<home>/config.yaml` добавьте:

```yaml
agent_plugins: [memory]
```

Настройки необязательны; ниже показаны значения по умолчанию:

```yaml
plugins:
  memory:
    threshold: 5
    interval: 24h
    # Имя профиля из models; если пропущено, используется default_model.
    model: chatting
    note_limit: 4096
    summary_limit: 16384
    context_limit: 16000
    api_timeout: 45s
    retry_interval: 5m
    max_pending_notes: 256
    max_pending_bytes: 262144
```

Размеры измеряются в UTF-8 байтах. Строгая схема отвергает неизвестные поля.
Threshold: 1–256; note_limit: 1–16384; summary_limit: 1–32768;
context_limit: 256–32000 (общий бюджет трёх блоков); max_pending_notes: 1–1024;
max_pending_bytes: от note_limit до 1048576. Интервалы положительные; api_timeout
не больше 45 секунд. Профиль должен существовать в `models`.

Установка и повторный `horizon init` не включают плагин и не изменяют память.
Пустой `agent_plugins` сохраняет прежний набор инструментов и инструкций.
После изменения конфигурации следующий ход получает новый снимок, перезапуск
Telegram-демона не нужен. Отключение плагина не удаляет файлы.

## Уровни и контекст

Один home соответствует одному агенту и одному пользователю. Многопользовательская
идентичность внутри home пока не поддерживается; для независимых пользователей
нужны разные home. Agent/user общие для сессий и директорий этого home.
Workspace соответствует нормализованному абсолютному cwd (включая разрешение
symlink); корень Git не ищется, подкаталог считается отдельным workspace.

- `agent`: собственные устойчивые рабочие выводы агента.
- `user`: подтверждённые сведения о пользователе и предпочтения.
- `workspace`: решения и особенности конкретной директории.

Модель получает `memory__add(scope,text)` и `memory__read(scope)`. Плагин советует
сохранять полезные устойчивые сведения, избегая секретов и непроверенных догадок.
Воспоминания — данные с источником, не инструкции поверх текущей задачи/AGENTS.md.
В снимке 0–3 непустых блока в порядке agent/user/workspace: «Долгая память»
(резюме), затем «Краткая память» (заметки по времени). Ограничение контекста
с явной отметкой пропуска меняет только представление. `memory__read` возвращает
такое же ограниченное представление выбранного уровня. Текущий снимок не меняется
после add; следующий ход увидит записанное. Полное состояние показывает CLI show.

Read позволяет чтение, запрещает add и обслуживание до запуска инструмента.
Write/full разрешают память в home. Наследуемый `HORIZON_INHERITED_ACCESS`
имеет приоритет, в том числе для CLI. Прямые инструменты доверенных расширений
не проходят Jev; декларации эффектов не являются песочницей ОС.

## Команды и сжатие

```sh
horizon memory add --scope user --text 'Предпочитает краткие ответы по-русски'
horizon memory add --scope workspace --text 'Сборка через make' --id project-build
horizon memory show --scope user
horizon memory compact --scope workspace
horizon memory clear --scope agent
horizon memory show --scope workspace --workspace /absolute/path
horizon memory watch --period 1m
```

Scope обязателен кроме watch, который обходит существующие уровни этого home.
Ручной workspace доступен только CLI; инструментам модель не задаёт пути.
Команды возвращают JSON в stdout, диагностику в stderr; коды 0/1/2/130 означают
успех/ошибку/неверные аргументы или конфигурацию/отмену. Metadata/help работают
без конфигурации. Watch работает в foreground, отменяется Ctrl+C/SIGTERM;
его можно запускать внешним планировщиком. Служба автоматически не устанавливается.

Сжатие происходит при достижении threshold заметок на уровне либо истечении
interval: перед следующим непустым resume, после add или при проверке watch.
Без watch таймер сам процесс не запускает. Первый интервал отсчитывается от
первой заметки, последующие — от последнего успешного сжатия. При пустых pending
модель не вызывается, даже вручную. Sessions compact читает память без её
обслуживания. Read также пропускает обслуживание.

Для сжатия отправляются только прежнее резюме и новые заметки выбранного уровня
обычным запросом Responses (`store: false`, без инструментов и истории сессии).
Это отдельный платный запрос к диалоговому провайдеру; профиль выбирается через
plugins.memory.model. `/responses/compact` не используется. Бюджет — две попытки
до начала SSE, не больше api_timeout суммарно. Полный ответ ограничен 1 МиБ.
Записи/служебные операции плагина хост автоматически не повторяет.

После ошибки сохраняются прежнее резюме и все pending notes; автоматические
попытки ограничены retry_interval, ручной compact может обойти задержку.
Успех add возвращает saved/id/duplicate и отдельный статус compaction: отказ
сжатия не отменяет запись и не требует повторного add. При заполнении pending
новая запись отклоняется явно; существующие заметки не удаляются.

## Хранение и конкуренция

Файлы: `<home>/memory/agent.json`, `user.json`, `workspaces/<workspace-id>.json`.
JSON имеет format_version 1, scope, путь workspace, revision/generation, summary,
pending notes (ID, UTC, text), время успешного сжатия и последней попытки.
Отсутствие файла означает пустую память без создания каталогов. Повреждение
или несовместимая версия — ошибка, не пустое состояние.

Запись атомарная, каталоги создаются 0700, файлы 0600. Постоянный `.json.lock`
защищает состояние; `.json.compact.lock` — отдельный запрос сжатия. Сжиматель
берёт сначала compaction, затем короткую state-блокировку; обратного захвата нет.
Во время API состояние не заблокировано. После успеха удаляются только заметки
из входного снимка; concurrent add остаётся pending. Clear меняет generation,
поэтому прежнее резюме не может восстановить очищенную память. Занятый уровень
при автоматическом обслуживании пропускается, второй watcher не дублирует запрос.
Lock-файлы не удаляются. Полные сжатые заметки не архивируются бесконечно.

ID операции инструмента задаёт хост из session/turn/call ID; CLI генерирует ID
или принимает --id. Повтор ID с тем же текстом не добавляет заметку, другой текст
даёт конфликт. Отдельный журнал хранит хеш текста и максимум 1024 ID; записи старше
90 дней удаляются при следующем добавлении. За этой границей дедупликация не
гарантируется; пока исходная заметка pending, её ID также проверяется. Clear
удаляет память, сохраняя ограниченный журнал ID, чтобы повтор не вернул очищенную
заметку. При plugin_outcome_unknown сначала проверяйте фактическое состояние.
