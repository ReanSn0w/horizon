# Agent Timer

`agent-timer` передаёт задачи по расписанию в очередь Horizon daemon.

```sh
horizon manager plugins install daemon
horizon manager plugins install agent:timer
horizon agent timer validate
```

Добавьте `timer` к существующим именам в `plugins.daemon.adapters` и запустите
`horizon daemon start`. Установка службы не запускает. Для разработки
`make install-agent-timer` собирает этот же бинарник в `HORIZON_HOME/bin`.

```yaml
plugins:
  daemon:
    adapters: [timer]
  agent-timer:
    access: write
    reload_interval: 30s
```

По умолчанию задачи получают `write`. Для задач, которые только читают данные, можно указать `read`.
`full` доступен только если supervisor запущен с унаследованным `full`.
При недостаточном унаследованном доступе адаптер сообщает об ошибке запуска.
Каталог перечитывается раз в 30 секунд по умолчанию. Интервал перечитывания
задаётся Go duration от `1s` и не меняет временную сетку расписания.

## Файл таймера

Пример файла `<home>/timers/check-reports.md`.

```markdown
---
name: Проверка отчётов
description: Обработать новые файлы в reports/
workspace: /absolute/path/to/project
schedule:
  cron: "0 10 * * 1-5"
  timezone: Europe/Moscow
  windows:
    - start: "09:00"
      end: "21:00"
enabled: true
---

Найди новые файлы в reports/. Обнови список обработанных файлов
в state/processed.json внутри workspace.
```

ID берётся из имени файла, допускает 1–64 строчные ASCII-буквы, цифры, дефисы
и подчёркивания и начинается с буквы или цифры. Переименование создаёт новый ID.
`name` и `description` обязательны. Workspace должен быть существующим абсолютным
каталогом, символические ссылки в нём разрешаются до физического пути. Валидатор
проверяет и отключённые определения. При отсутствии `enabled` действует `true`.
Принимаются только непосредственные обычные файлы `.md` в UTF-8 размером до
128 КиБ. Символические ссылки вместо файла или каталога расписаний запрещены.

В `schedule` укажите ровно одно из `every` и `cron`, а также IANA timezone.
`every` — Go duration от `1m` на фиксированной сетке Unix epoch. Например,
`every: 30m` вычисляется по абсолютному времени, включая переходы DST.
Пятичастный cron использует местные минуты, часы, день месяца, месяц (1–12)
и день недели (воскресенье 0 или 7). Допустимы числа, диапазоны, списки, шаги
и `*`. Когда оба поля дней ограничены, срабатывает их логическое OR. Cron
пропускает отсутствующую локальную минуту при переводе часов вперёд и выбирает
первую копию повторённой минуты при переводе назад. Поиск ограничен восемью
годами от опорной даты (для `every` от первого возможного слота).

Окна `HH:MM` действуют от включённой границы начала до исключённой границы
конца и могут проходить через полночь. Пересекающиеся окна образуют единый
разрешённый период. Без `windows` задача допустима круглосуточно. Открытие
окна само по себе запуска не создаёт. Задача, ещё ожидающая исполнения на
границе окна, пропускается. Уже начатая задача завершается штатно.

## Запуск и восстановление

Таймер начинает новую сессию с обычными инструкциями, навыками и включённой
памятью. Для накопленного состояния используйте файлы workspace.
В одном нормализованном workspace одновременно исполняется один таймерный ход,
а в разных workspace таймеры могут работать параллельно в пределах daemon.
Слоты занятого таймера или переполненной очереди пропускаются. Адаптер допускает
задержку обработки текущего слота до 2 секунд и отбрасывает прошедшие слоты
при запуске, сне и скачке часов. Изменённые и заново включённые таймеры
планируются на будущие слоты. Демон фиксирует начало работы и отмену ожидающей
задачи под одной блокировкой. Если первым зафиксирован старт, задача использует
старый снимок поручения. Повреждённый файл исключается из планирования.

```sh
horizon agent timer validate [timer-id]
horizon agent timer status [timer-id]
horizon agent timer unblock <timer-id>
```

`validate` и `status` работают без демона и без обращения к провайдеру.
Состояние срабатываний хранится в `<home>/timer/state.json`. Если подтверждение
submit потеряно, адаптер сначала ищет задачу по устойчивому operation ID.
Неизвестный исход блокирует таймер. Проверьте записанный task ID и историю,
затем используйте `unblock`, чтобы разрешить будущие слоты. Прежняя задача
не повторяется. Результаты остаются в истории Horizon и состоянии демона,
статусы — в диагностике daemon. Для уведомлений поручение может использовать
установленное отправляющее расширение. Таймер не задаёт Telegram chat ID.
