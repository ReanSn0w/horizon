# Agent Timer

`agent-timer` передаёт задачи по расписанию в очередь Horizon daemon.

```sh
horizon manager plugins install agent
horizon manager plugins install agent:timer
horizon agent timer validate
```

Добавьте `timer` к существующим именам в `plugins.agent.adapters` и запустите
`horizon agent start`. Установка службы не запускает. Для разработки
`make install-agent-timer` собирает этот же бинарник в `HORIZON_HOME/bin`.

```yaml
plugins:
  agent:
    adapters: [timer]
  agent-timer:
    access: write
    reload_interval: 30s
```

По умолчанию задачи получают `write`. Для задач, которые только читают данные, можно указать `read`.
`full` доступен только если supervisor запущен с унаследованным `full`.
При недостаточном унаследованном доступе адаптер сообщает об ошибке запуска.
Каталог перечитывается раз в 30 секунд по умолчанию. Интервал перечитывания
задаётся Go duration от `1s` и не меняет временную сетку расписания.

## Файл таймера

Пример файла `<home>/timers/check-reports.md`.

```markdown
---
name: Проверка отчётов
description: Обработать новые файлы в reports/
workspace: /absolute/path/to/project
schedule:
  cron: "0 10 * * 1-5"
  timezone: Europe/Moscow
  windows:
    - start: "09:00"
      end: "21:00"
enabled: true
---

Найди новые файлы в reports/. Обнови список обработанных файлов
в state/processed.json внутри workspace.
```

ID берётся из имени файла, допускает 1–64 строчные ASCII-буквы, цифры, дефисы
и подчёркивания и начинается с буквы или цифры. Переименование создаёт новый ID.
`name` и `description` обязательны. Если `workspace` отсутствует, используется
`<home>/workspace/<timer-id>`: для `check-reports.md` это `workspace/check-reports`.
Поле `name` на путь не влияет. Каталог создаётся с правами `0700` перед отправкой
допустимого запуска в daemon, затем повторно используется вместе со всеми файлами.
`list`, `validate`, `enable`/`disable`, выключенные таймеры и пропущенные слоты
его не создают. Переименование файла меняет ID и путь по умолчанию; заметки
автоматически не перемещаются.

Явный `workspace` должен быть существующим абсолютным каталогом; пустая строка,
`null` и неверный тип являются ошибкой. Символические ссылки разрешаются до
физического пути. Валидатор
проверяет и отключённые определения. При отсутствии `enabled` действует `true`.
Принимаются только непосредственные обычные файлы `.md` в UTF-8 размером до
128 КиБ. Символические ссылки вместо файла или каталога расписаний запрещены.

В `schedule` укажите ровно одно из `every` и `cron`, а также IANA timezone.
`every` — Go duration от `1m` на фиксированной сетке Unix epoch. Например,
`every: 30m` вычисляется по абсолютному времени, включая переходы DST.
Пятичастный cron использует местные минуты, часы, день месяца, месяц (1–12)
и день недели (воскресенье 0 или 7). Допустимы числа, диапазоны, списки, шаги
и `*`. Когда оба поля дней ограничены, срабатывает их логическое OR. Cron
пропускает отсутствующую локальную минуту при переводе часов вперёд и выбирает
первую копию повторённой минуты при переводе назад. Поиск ограничен восемью
годами от опорной даты (для `every` от первого возможного слота).

Окна `HH:MM` действуют от включённой границы начала до исключённой границы
конца и могут проходить через полночь. Пересекающиеся окна образуют единый
разрешённый период. Без `windows` задача допустима круглосуточно. Открытие
окна само по себе запуска не создаёт. Задача, ещё ожидающая исполнения на
границе окна, пропускается. Уже начатая задача завершается штатно.

## Запуск и восстановление

Таймер начинает новую сессию с обычными инструкциями, навыками и включённой
памятью. Для накопленного состояния используйте файлы workspace.
В одном нормализованном workspace одновременно исполняется один таймерный ход,
а в разных workspace таймеры могут работать параллельно в пределах daemon.
Слоты занятого таймера или переполненной очереди пропускаются. Адаптер допускает
задержку обработки текущего слота до 2 секунд и отбрасывает прошедшие слоты
при запуске, сне и скачке часов. Изменённые и заново включённые таймеры
планируются на будущие слоты. Демон фиксирует начало работы и отмену ожидающей
задачи под одной блокировкой. Если первым зафиксирован старт, задача использует
старый снимок поручения. Повреждённый файл исключается из планирования.

```sh
horizon agent timer validate [timer-id]
horizon agent timer list [--json]
horizon agent timer status [timer-id]
horizon agent timer enable <timer-id>
horizon agent timer disable <timer-id>
horizon agent timer run <timer-id>
horizon agent timer unblock <timer-id>
```

`list`, `validate` и `status` работают без демона и без обращения к провайдеру.
`list` показывает каждый Markdown-файл каталога, в том числе ошибку отдельного
повреждённого определения; `--json` выдаёт массив объектов для скриптов с
эффективным `workspace` и признаком `default_workspace`. Успешный `validate`
тоже печатает выбранный workspace.
`enable` и `disable` требуют права записи, проверяют определение и атомарно
меняют только поле `enabled` с сохранением остального файла. Повторный вызов
не переписывает файл. Планировщик увидит изменение при следующем перечитывании;
ожидающая в очереди устаревшая задача отменяется, уже начатая завершается.
`run` требует права записи, валидный включённый таймер и работающий daemon.
Команда ставит свежую задачу в долговечную очередь с workspace, доступом и
поручением из файла и печатает task ID. Следующий плановый слот не меняется.
Для одного timer ID допускается только одна ожидающая или выполняемая задача.
При потере ответа операция сохраняется в `<home>/timer/manual-ID.json`;
повторный `run` сначала ищет её по operation ID, затем безопасно повторяет
ту же операцию. Этот файл содержит текст поручения и имеет права `0600`.
Состояние срабатываний хранится в `<home>/timer/state.json`. Если подтверждение
submit потеряно, адаптер сначала ищет задачу по устойчивому operation ID.
Неизвестный исход блокирует таймер. Проверьте записанный task ID и историю,
затем используйте `unblock`, чтобы разрешить будущие слоты. Прежняя задача
не повторяется. Результаты остаются в истории Horizon и состоянии демона,
статусы — в диагностике daemon. Для уведомлений поручение может использовать
установленное отправляющее расширение. Таймер не задаёт Telegram chat ID.

## Nap и постоянные заметки

Готовый [nap.md](../../examples/timers/nap.md) выключен и не требует подстановки
workspace. Из корня репозитория скопируйте его только при отсутствии файла
назначения (HORIZON_HOME должен указывать на подготовленный home):

```sh
(
  set -euC
  umask 077
  mkdir -p "$HORIZON_HOME/timers"
  cat examples/timers/nap.md > "$HORIZON_HOME/timers/nap.md"
)
horizon agent timer validate nap
```

Если файл уже существует, копирование завершится ошибкой без перезаписи.
Проверьте поручение и расписание, затем явно включите: `horizon agent timer enable nap`.
Работающий supervisor подхватит изменение при следующем перечитывании каталога.
Обновление существующего nap, его `AGENTS.md` и заметок выполняется отдельно
пользователем; установка не заменяет эти файлы.

Nap читает `notes.md`, ведёт предварительные наблюдения и очередь в
`pending.json`/`processed.json`. Workspace `AGENTS.md` автоматически включается
в инструкции начала каждого хода; остальные файлы модель читает инструментами.
Единичное наблюдение не обязано становиться правилом. Повторный анализ того же
хода не считается независимым подтверждением. Nap может улучшать навыки и
создавать выключенные предложения таймеров. Включение требует конкретного
поручения пользователя на регулярную работу.

Истории запусков сохраняются с меткой `timer` и скрыты в обычном
`sessions list`, включая `--all`. Для диагностики используйте
`horizon sessions list --all --include-timers --json` и
`horizon sessions read --all --id ID`. Истории не удаляются автоматически.
Старые сессии без метки остаются видимыми; отсутствие метки не доказывает
пользовательское происхождение. Nap не добавляет диагностическую выборку
таймеров в анализируемые диалоги.

Существующий nap с явным workspace продолжает работать по прежнему пути.
Для перехода остановите запуски и дождитесь завершения активного хода,
перенесите `AGENTS.md`, заметки и очередь в `<home>/workspace/nap`, не
перезаписывая имеющиеся файлы. Удалите поле `workspace`, выполните
`horizon agent timer validate nap`, проверьте напечатанный путь и возобновите
запуски. Переход без переноса файлов начнёт работу с пустым состоянием.
