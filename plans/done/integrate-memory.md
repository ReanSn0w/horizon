## Что мы делаем?

Переносим память из `plugins/memory` во внутренний пакет `harness/internal/memory`.
Harness непосредственно читает контекст и выполняет инструменты памяти;
CLI `horizon memory add/show/compact/clear/watch` работает без внешнего бинарника.
Удаляем плагин memory из новой поставки. Выполнять после
[интеграции decision](integrate-decision.md), используя проверенный там переход
управляемого компонента во встроенную возможность.

По указанию пользователя работа выполняется без новых коммитов, push, merge,
тегов и релиза. Существующие незакоммиченные изменения сохраняются. Выделение
agent, переработка Telegram, MCP и общий редизайн плагинов сюда не входят.

Предлагаемая политика: в новой конфигурации `memory.enabled: true`;
`memory.enabled: false` отключает контекст и инструменты в ходе, но оставляет
явные CLI-команды для просмотра и обслуживания данных. Для старой конфигурации
без новой секции сохраняем прежнее включение через `agent_plugins: [memory]`;
отсутствие memory в этом списке не должно неожиданно включать сбор памяти.

## Для чего мы делаем?

Память доказала необходимость как штатная возможность harness. Её использование
не должно зависеть от обнаружения бинарника и служебных JSON-вызовов плагина.
При этом перенос обязан сохранить существующие данные, режимы доступа,
дедупликацию и журналирование, включая поведение после неизвестного исхода.
