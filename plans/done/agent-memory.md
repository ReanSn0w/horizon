## Что мы делаем?

Добавляем плагин `memory` с тремя независимыми уровнями памяти: агент,
пользователь и workspace. Каждый уровень содержит долгую память — текст
последнего сжатия — и краткую память — заметки, ещё не включённые в этот текст.
Агент самостоятельно выбирает полезные сведения и добавляет их инструментом.
Сжатие объединяет прежний текст и новые заметки; потеря второстепенных деталей
допустима. Пустой уровень не добавляется в контекст.

Сначала расширяем Horizon общим механизмом подключения контекста и function
tools из явно включённых плагинов. Затем реализуем память через этот механизм,
без специальных знаний о памяти в основном цикле агента. Используем Go,
существующий Responses-клиент и локальные JSON-файлы; новая база данных,
векторный поиск и отдельный сервис не нужны.

Предлагаемые решения первой версии:

- Один `HORIZON_HOME` соответствует одному агенту и одному пользователю.
  Их память общая для всех сессий этого home. Несколько пользователей внутри
  одного home и отдельные идентичности агентов пока не поддерживаются.
  Память workspace общая для сессий ровно этой рабочей директории.
- Данные хранятся в `<home>/memory/agent.json`, `<home>/memory/user.json`
  и `<home>/memory/workspaces/<workspace-id>.json`. Workspace определяется
  существующей нормализацией пути и MD5 в `internal/session`, без поиска Git.
- Порог по умолчанию — 5 новых заметок **на уровень**, интервал — 24 часа.
  Для первого сжатия интервал отсчитывается от первой новой заметки,
  для последующих — от последнего успешного сжатия. Время без новых заметок
  не вызывает запрос модели. Значения настраиваются в `plugins.memory`.
- Порог проверяется после добавления; истечение интервала — перед снимком
  нового хода и после добавления. `memory watch` обеспечивает периодическую
  проверку также во время простоя; это отдельный явно запускаемый процесс.
  Сам Horizon остаётся процессом одного хода и не запускает скрытый демон.
- В контекст попадают от 0 до 3 блоков в порядке `agent`, `user`, `workspace`.
  В каждом сначала долгая память, затем несжатые заметки по времени записи.
  Снимок остаётся неизменным до следующего хода; инструмент подтверждает
  добавление сразу, но не перестраивает системное сообщение посреди хода.
- Для памяти модель получает `memory__add` и `memory__read`; обслуживание
  доступно командами `horizon memory add/show/compact/watch/clear`.
  Модель не получает отдельного инструмента удаления всей памяти.
- Сжатие — отдельный запрос обычного текстового резюме через Responses API
  с `store: false`, без инструментов. `/responses/compact` предназначен для
  контекста сессии и не используется как хранилище читаемого текста памяти.
- Сжатие не перечитывает историю диалога: вход — только прежняя долгая память
  и новые заметки выбранного уровня. Полные старые заметки после успешного
  сжатия удаляются из активного состояния; бесконечный архив не создаётся.

Это предлагаемые параметры и границы для реализации, а не уже существующие
возможности Horizon. Отключение плагина сохраняет данные на диске.

## Для чего мы делаем?

История сейчас принадлежит сессии; инструкции собираются из home, навыков
и workspace. Установленные плагины предоставляют CLI-команды, но не дополняют
снимок инструкций и статический реестр инструментов. Нужен общий контракт
расширений, чтобы память переживала смену сессии и подключалась независимо
от основного бинарника.

В текущем коде `internal/config` уже принимает `plugins.<имя>`, как описано
в `docs/PLUGINS.md`; ограничение на этот ключ в корневом `AGENTS.md` устарело.
При реализации исправляем это расхождение вместе с новыми контрактами.
