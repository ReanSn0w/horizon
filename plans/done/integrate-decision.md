## Что мы делаем?

Переносим CLI `horizon decision` из `plugins/decision` в harness, сохраняя
существующий клиент и политику Jev в `harness/decision`. Убираем отдельный
бинарник `horizon-decision` из новой поставки после подключения встроенной команды.
Выполнять перед [интеграцией памяти](integrate-memory.md).

Работа ведётся поверх текущего переноса harness и незакоммиченного перемещения
Telegram в `agent/legacy/telegram/`. По указанию пользователя новые коммиты,
push, merge, теги и релиз пока не выполняются. Историю не переписываем.
Переработка Telegram, MCP и протокола внешних плагинов в задачу не входят.

## Для чего мы делаем?

Jev уже используется ядром для оценки shell-команд, но самостоятельный запрос
решения всё ещё требует установленного плагина. Встроенная команда устраняет
эту зависимость, сохраняя терминальный интерфейс для пользователя и шлюзов.

Удаление записи из каталога требует совместимости поставки: текущий updater
передаёт старый список Installed в Closure нового каталога и отклонит исчезнувший
компонент. Новый код updater не исправит уже установленный старый бинарник;
для такого перехода нужен проверенный путь через новый установочный комплект.
