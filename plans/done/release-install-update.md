## Что мы делаем?

Добавляем GitHub Actions workflow для проверок и выпуска готовых архивов,
`install.sh` для первоначальной установки, плагин `update` для обновления
Horizon вместе с установленными плагинами и плагин `plugins` для просмотра,
установки и удаления плагинов с учётом зависимостей.

Источник поставки — только `ReanSn0w/horizon` на GitHub. Один тег задаёт
версию основного бинарника и всех официальных плагинов. Для Linux и macOS
собираются отдельные архивы для amd64 и arm64; каждый содержит весь комплект.
Установщик первоначально выбирает только `horizon`, `horizon-update` и
`horizon-plugins`. Остальные устанавливаются явно. Зависимость
`telegram -> decision` обязательна на уровне поставки, хотя сейчас decision
требуется Telegram именно для режима собеседника.

Каталог с описаниями и зависимостями публикуется вместе с каждым релизом.
Установка плагина использует каталог и архив версии установленного Horizon,
обновление — каталог целевого релиза. Ветка master не является каталогом
для уже выпущенных версий. Внешние репозитории, независимые версии плагинов,
фоновые обновления, цикличные задачи и заметки в эту работу не входят.

Новые пути и интерфейсы ниже — предлагаемые части реализации. Существующие
точки интеграции: `internal/cli`, `internal/plugins`, `plugins/`, `Makefile`,
`README.md`, `docs/PLUGINS.md`, `internal/e2e`. Обычная установка из исходников
остаётся доступной.

## Для чего мы делаем?

Сейчас установка требует Go и исходников, а Makefile отдельно собирает
основной бинарник и выбранные плагины. Нет общего номера установленной
поставки, автоматической доставки зависимостей и штатного обновления.
Новый путь должен позволить установить личный инструмент без Go и затем
управлять им через Horizon, сохраняя пользовательские данные.
