## Что мы делаем?

Добавляем `plugins/gateway/` — плагин `horizon gateway` для одного Telegram-бота
на Horizon home. Первая версия работает через long polling с текстовыми
сообщениями в личном диалоге владельца, группах и супергруппах. На чат
выделяется отдельный workspace и закреплённая сессия Horizon. Темы Telegram
разделяют эту сессию, но ответы возвращаются в тему исходного обращения.
Вложения, голос, каналы, webhook, SysV init.d и OpenRC не входят в эту версию.

Стек — существующий Go, `go-flags`, `yaml.v3`, стандартные `net/http` и
`os/exec`. Gateway запускает Horizon и установленный плагин `decision`
через CLI, не изменяя внутренние JSON-сессии. Настройки находятся в
`plugins.gateway` общего `config.yaml`. Ограниченное оперативное состояние
хранится отдельно в YAML с атомарной записью и блокировкой ОС.
Внешняя БД и универсальный фреймворк транспортов не требуются.

Начальные настройки, добавляемые `gateway init`:

~~~yaml
plugins:
  gateway:
    telegram:
      bot_token: ""
      owner_user_id: 0
    workspace_dir: /absolute/path/to/horizon-home/workspaces/telegram
    private_access: write
    group_access: read
    group_defaults:
      owner_only: true
      response_mode: mention
    conversation:
      history_messages: 20
      reply_threshold: 0.7
    max_parallel_chats: 2
    groups: {}
~~~

При обнаружении группы gateway добавляет `groups."<chat_id>"` с копией
`owner_only` и `response_mode` из `group_defaults`. Существующие настройки
сохраняются; название и другие изменяемые сведения находятся в реестре.
Режимы доступа принимают `read|write|full`. Личные обращения по умолчанию
используют `write`, групповые — `read`.

Пример индивидуальной настройки группы внутри `plugins.gateway`:

~~~yaml
groups:
  "-1001234567890":
    owner_only: false
    response_mode: mention
~~~

`owner_only` — независимый фильтр автора. Сочетание `owner_only: false` и
`response_mode: mention` позволяет любому участнику обратиться через
`@username` бота. При `owner_only: true` остальные участники не вызывают
ответ даже по упоминанию, но их реплики могут входить в контекст группы.
Чужие личные сообщения игнорируются полностью; владельца определяет
числовой Telegram user ID.

В `mention` ответ вызывает точное упоминание бота. В `conversation`
упоминание допустимого автора вызывает ответ сразу, остальные сообщения
таких авторов оцениваются через `horizon decision -`. В запрос входят
несколько последних реплик, включая сообщения бота. Ответ запускается при
`should_reply.noul >= reply_threshold`. Ошибка Jev означает отсутствие
спонтанного ответа. Порог 0.7 — начальная настраиваемая эвристика.
Reply на сообщение бота без `@` не обходит эти правила.

Контекст собирается только из полученных updates и известных gateway
отправок; старая переписка до подключения не импортируется. Для наблюдения
обычных групповых сообщений следует отключить Privacy Mode либо назначить
бота администратором ([Telegram FAQ](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get)).

Команды первой версии:

~~~sh
horizon gateway init
horizon gateway start
horizon gateway list
horizon gateway list --json
horizon gateway send --chat -1001234567890
horizon gateway send --chat -1001234567890 -m 'Продолжи обсуждение итогов встречи' --wait
horizon gateway service install --manager launchd
horizon gateway service install --manager systemd
horizon gateway service start
horizon gateway service stop
horizon gateway service restart
horizon gateway service status
horizon gateway service uninstall
~~~

`gateway list` показывает таблицу, в которой рядом с `CHAT ID` находится
столбец `NAME` с человекочитаемым названием: название группы либо имя
владельца в личном диалоге. Если имени нет, используется `@username`,
а при его отсутствии — `Chat <id>`. Название обновляется по полученным
событиям Telegram; таблица показывает последнее известное значение из
локального реестра. В `list --json` то же значение доступно в поле `name`.
Одинаковые названия допустимы: идентификатором для `send` остаётся chat ID.
Отдельная команда получения названия по ID в первой версии не требуется.

`start` работает в foreground. `send` требует работающий gateway,
ставит новый ход в общую очередь чата и возвращает ID задания;
`--wait` ожидает итоговый статус доставки. `-m` задаёт поручение модели,
а без него используется просьба продолжить разговор по истории.
Команда не отправляет `-m` буквально и не вызывает Jev для решения,
стоит ли отвечать; режим доступа и сессия определяются целевым чатом.
Для форумной группы параметр `--thread ID` задаёт тему явно;
без него используется тема последнего текстового обращения,
а при отсутствии однозначного адресата возвращается ошибка.

Поддерживаются пользовательские LaunchAgent на macOS и `systemd --user`
на Linux. `service install` устанавливает описание автозапуска,
`service start` запускает процесс сейчас. Службы содержат абсолютный
путь к Horizon и выбранный home, но не токены.

## Для чего мы делаем?

Horizon выполняет один ход из терминала. Gateway даст ему постоянный канал
общения с отдельной историей и рабочим каталогом для каждого чата.
Повторно используются существующие инструменты, сессии и оценка команд Jev.
Разделение каталогов предотвращает смешение чатов при маршрутизации,
но не создаёт песочницу ОС и не меняет действующие гарантии `read/write/full`.

## Результат автоматических проверок

На macOS прошли `go test ./...`, `go vet ./...`, `go test -race ./...`,
`git diff --check`, установка `make install-all` во временный home и
валидация LaunchAgent через `plutil`. Собраны Horizon, decision и gateway
для macOS и Linux amd64. E2E запускает настоящие собранные бинарники через
локальные Telegram/Responses/Decisions API и проверяет очередь, ручной send,
имена, изоляцию чужой лички и восстановление без повторных отправок.

Нативный запуск LaunchAgent и systemd, реальный Telegram и провайдер
не проверялись. Сценарий продолжения находится в `plugins/gateway/README.md`.
Это отдельная проверка после настройки пользователем, а не выполненный smoke-тест.
