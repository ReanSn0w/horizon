## Что мы делаем?

Устраняем сбой браузерного плагина, при котором удалённый браузер создаётся, но `browser__navigate` возвращает `browser_error: remote browser action failed` для разных сайтов. Добавляем безопасную диагностику этапов CDP, воспроизводим фактическую причину и исправляем её в существующем Go-плагине. Проверяем не только создание сессии, но и получение содержимого страницы, повторное подключение отдельного процесса и очистку ресурсов.

Сохраняем инструменты `navigate/snapshot/click/type`, режим доступа `full`, создание браузера при первом URL и остановку после хода. Смена провайдера, новые инструменты, локальный браузер и ввод секретов в задачу не входят.

## Для чего мы делаем?

Пользователь наблюдает одинаковые отказы для Habr, Hacker News и Google. Это не доказывает отказ сайтов: `plugins/browser/cdp.go` заменяет любую ошибку `chromedp.Run` одной строкой, скрывая сбой подключения, подготовки вкладки, навигации или снимка. Точная причина пока не установлена.

`plugins/browser/api_live_test.go` проверяет только создание и остановку сессии. Локальные CDP-тесты используют имитацию сервера; E2E `TestBuiltBrowserPluginTurnAndCleanup` проверяет завершение хода и счётчики, но не подтверждает содержимое результатов, полученных моделью. Завершённый план реализации поэтому не является доказательством работоспособности реальной навигации.

## План

- [ ] Уточнить воспроизведение и границы сбоя.
  - [ ] Сверить установленный `horizon-browser` с текущими исходниками; записать выбранный home, версию или происхождение бинарника и параметры таймаутов без ключей и приватных URL.
  - [ ] Проверить путь от `browserLifecycle.open` через `runCDP` до сохранения `TargetID` и снимка; сопоставить его с текущим контрактом Browser Use и используемой версией chromedp.
  - [ ] Зафиксировать гипотезы для проверки: WebSocket-подключение, готовность удалённого браузера, создание/подключение вкладки, команды CDP, ожидание загрузки и вычисление снимка. Не выбирать исправление до получения причины.

- [ ] Сделать ошибки CDP пригодными для диагностики.
  - [ ] Разделить диагностику подключения/подготовки вкладки, действия и получения снимка в `plugins/browser/cdp.go` и `page.go`, сохранив текущий протокол ответа.
  - [ ] Возвращать ограниченную по размеру безопасную причину: отмену, таймаут, сетевой отказ, ошибку протокола или навигации; неизвестные ошибки не выдавать за установленную причину.
  - [ ] Исключить из результата и stderr CDP URL, его параметры авторизации, API-ключ, заголовки и произвольный ответ удалённого сервера; не передавать модели сырую ошибку через `%w` без обработки.
  - [ ] Добавить проверки диагностики для таймаута, отмены, отказа WebSocket и ошибки CDP с секретными маркерами в исходной ошибке.

- [ ] Воспроизвести дефект и исправить подтверждённую причину.
  - [ ] Получить диагностированный отказ на реальном Browser Use в отдельном временном home при явно разрешённой проверке аккаунта; не менять личные сессии и конфигурацию. Если аккаунт недоступен, оставить реальное воспроизведение незавершённым.
  - [ ] Воспроизвести выявленный механизм в контролируемом тесте, который падает на текущем поведении; сохранить только обезличенные данные протокола.
  - [ ] Внести минимальное исправление подключения, жизненного цикла вкладки или навигации по результату воспроизведения; не увеличивать таймаут вслепую и не повторять навигацию автоматически после неизвестного исхода.
  - [ ] Проверить сохранение вкладки между процессами: `navigate` возвращает содержимое, следующий `snapshot` подключается к тому же `TargetID`, повторный переход возвращает содержимое новой страницы.
  - [ ] Проверить остановку удалённой сессии после успешного, ошибочного и отменённого хода; не закрывать браузер другого выполняющегося хода.

- [ ] Усилить проверки наблюдаемого результата.
  - [ ] Расширить `plugins/browser/api_live_test.go`: в явно включаемом тесте открыть `https://example.com`, проверить URL и ожидаемый текст, затем получить новый снимок через повторное подключение. Остановку выполнять и при ошибке; её неудачу показывать отдельно от исходного сбоя.
  - [ ] В `internal/e2e/browser_plugin_test.go` проверить переданные модели результаты `navigate` и `snapshot`: `ok`, URL, текст, непустой `snapshot_id`; итоговый ответ модели `done` не считать достаточной проверкой.
  - [ ] Добавить E2E диагностированного отказа: модель получает безопасную причину, ход сохраняется, завершающий вызов останавливает созданную сессию.
  - [ ] Проверить, что обычный `go test ./...` не обращается к реальному провайдеру и не создаёт оплачиваемые браузеры.

- [ ] Проверить результат и обновить документацию.
  - [ ] Выполнить `gofmt` для изменённых Go-файлов.
  - [ ] Выполнить `go build -o /tmp/horizon-dev .` и `go build -o /tmp/horizon-browser-dev ./plugins/browser`.
  - [ ] Выполнить `go test ./...`.
  - [ ] Выполнить `go vet ./...`.
  - [ ] Выполнить `go test -race ./...`, если исправление затронет отмену, процессы, блокировки или параллельный доступ.
  - [ ] При явно разрешённом использовании аккаунта выполнить `HORIZON_BROWSER_API_CHECK=1 go test ./plugins/browser -run TestConfiguredBrowserUseAPI -v` с отдельным временным `HORIZON_HOME`; конфигурацию подготовить без вывода секретов. Проверить, что созданная сессия остановлена.
  - [ ] В установленном исправленном плагине проверить исходный пользовательский сценарий с Habr и Hacker News; отделить возможный отказ конкретного сайта от ошибки транспорта и снимка.
  - [ ] Обновить `plugins/browser/README.md` и соответствующее описание в `docs/TOOLS.md`: диагностика, фактический охват live-теста и способ проверки установленной версии.
  - [ ] В отчёте указать подтверждённую причину, исправление и фактически выполненные проверки; явно отметить недоступные реальные проверки, не объявляя навигацию подтверждённой по одним имитациям.
