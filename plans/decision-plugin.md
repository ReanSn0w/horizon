## Что мы делаем?

Добавляем в `plugins/decision/` отдельную команду `horizon decision`, которая
принимает один JSON-запрос из файла или stdin (`-`), отправляет его через
существующий `internal/decision.Client` и выводит JSON-ответ в stdout. Флаг
`-o <путь>` записывает тот же ответ в файл. Вход повторяет полезную часть
текущего запроса Decisions API: `state` и `questions` с типами `noul`, `choice`
или `score`. Поля `model`, URL и ключ во входном JSON и аргументах команды не
поддерживаются: плагин берёт их из `decision` в выбранном `config.yaml`.
Необязательная секция `plugins.decision` зарезервирована для будущих
собственных настроек плагина; в первой версии дополнительных параметров нет.

Предлагаемая форма вызова: `horizon decision request.json` или
`horizon decision - -o result.json`. Например, вход:

```json
{
  "state": {"proposal": "release version 1.2"},
  "questions": {
    "ready": {"type": "noul", "instructions": "Is the proposal ready to release?"}
  }
}
```

Выход — один JSON-объект с полями ответа Jev (`id`, `model`, `provider`,
`answers`, `usage`) и завершающим переводом строки. Плагин не создаёт ход
агента и не меняет сессии. Он не устанавливается автоматически: исходники
собираются в исполняемый `<home>/plugins/horizon-decision` по действующему
протоколу плагинов.

## Для чего мы делаем?

Сейчас модель решений доступна через внутренний Go-клиент, но у пользователя
нет простой команды для отдельных структурированных оценок. Плагин даст такой
доступ без повторной настройки провайдера при каждом вызове. Один раз настроить
секцию `decision` в Horizon всё же необходимо: отдельный процесс не получает
ключ от хоста и прочитает его из выбранного home.

## План

- [ ] Зафиксировать пользовательский контракт команды и JSON.
  - [ ] Принять ровно один позиционный аргумент: путь к UTF-8 JSON-файлу или `-` для stdin; определить `-o <путь>` и `--help` без дополнительных настроек модели.
  - [ ] Считать вход одним JSON-объектом `{state, questions}`; отклонять второй JSON-объект, неизвестные верхнеуровневые поля и попытки передать `model`, URL или ключ.
  - [ ] Сохранить имена, типы и смысл вопросов из `internal/decision.Request`; использовать ограничения размера запроса и проверку вопросов существующего клиента.
  - [ ] Определить успешный вывод как один сериализованный `internal/decision.Response` с переводом строки; диагностику направлять только в stderr, при ошибке не выводить частичный JSON.

- [ ] Добавить общее пространство настроек плагинов в `config.yaml`.
  - [ ] Разрешить необязательный верхнеуровневый `plugins` в строгом загрузчике `internal/config` без изменения проверки остальных известных полей.
  - [ ] Сохранить вложенные настройки по имени плагина доступными соответствующему плагину, не навязывая общей схемы его параметров.
  - [ ] Проверить загрузку старого конфига без `plugins`, пустого `plugins.decision` и произвольных полей внутри секции плагина.
  - [ ] Обновить оба совпадающих шаблона `config.example.yaml` и `internal/bootstrap/assets/config.yaml` пояснением о необязательной секции без добавления фиктивных настроек.

- [ ] Реализовать исполняемый плагин в `plugins/decision/`.
  - [ ] Добавить служебный `horizon-plugin-metadata` версии протокола 1 и локальную справку; эти вызовы не должны читать конфигурацию и обращаться к сети.
  - [ ] Разобрать путь входа и `-o`, прочитать ограниченный входной JSON и вернуть адресные ошибки для неверных аргументов или данных.
  - [ ] Разрешить home через `internal/config.ResolveHome`, загрузить `config.yaml`, проверить `RequireDecision` и получить endpoint через `DecisionEndpoint`.
  - [ ] Убедиться, что отсутствие `plugins.decision` не мешает запуску; не дублировать туда `decision.provider` или `decision.model`.
  - [ ] Передать настроенные ключ и модель в `internal/decision.Client`, не добавляя ключ в ошибки, сериализуемый ответ или метаданные.
  - [ ] Записать успешный ответ в stdout либо атомарно создать или заменить файл `-o` с правами `0600`; не оставлять частичный файл при ошибке запроса или записи.
  - [ ] Возвращать ненулевой код при ошибках ввода, конфигурации, провайдера и вывода, сохраняя чистый stdout для использования в конвейере.

  - [ ] Проверить через локальный HTTP-сервер, что запрос использует модель, endpoint и Bearer-ключ из выбранного `HORIZON_HOME`, а JSON ответа соответствует `internal/decision.Response`.
