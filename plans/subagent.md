## Что мы делаем?

Создаём `horizon-subagent` в предлагаемом каталоге `plugins/subagent` —
CLI-плагин с расширением инструментов модели, включаемым через
`agent_plugins: [subagent]`. Он является короткоживущим клиентом Unix-сокета
из [daemon.md](daemon.md), не держит собственную очередь и не запускает Horizon.
Сами подагенты — обычные процессы Horizon с отдельными сессиями.

Первый вариант запускает ребёнка с явным текстом задачи в workspace родителя,
без автоматического копирования истории или создания worktree. Сообщения
доставляются между ходами. Общие файлы workspace остаются общими; отдельная
сессия не изолирует изменения файлов. Telegram и timer в эту задачу не входят.

## Для чего мы делаем?

Делегирование должно быть доступно обычному Horizon независимо от внешнего
канала. Отдельный клиент сохраняет управление процессами в демоне и использует
существующие схемы, проверки эффектов и pending/known/unknown ядра.

## План

- [ ] Согласовать клиентский контракт с daemon.
  - [ ] Использовать версионируемый протокол, идентификаторы и дедупликацию daemon; реализацию выполнять после соответствующих этапов daemon.md.
  - [ ] Описать в новом `docs/SUBAGENT.md` инструменты spawn, list, read, send, wait и cancel с полными именами `subagent__<tool>`.
  - [ ] Определить строгие схемы аргументов и результаты: ID ребёнка/задачи, состояние, курсор, ограниченный текст результата и явное продолжение при усечении.
  - [ ] Зафиксировать область видимости: управление детьми текущей родительской сессии, без произвольного доступа к задачам Telegram и других клиентов.
  - [ ] Зафиксировать ограничения первого варианта: отдельная пустая сессия, явное поручение, тот же workspace, отсутствие live-steering и автоматического слияния результатов.

- [ ] Подключить плагин к существующему хосту.
  - [ ] Реализовать metadata, describe, context и tool по `internal/plugins/agent.go`; не добавлять отдельный реестр инструментов ядра.
  - [ ] Проверять handshake во время подготовки в пределах текущего двухсекундного бюджета; недоступный явно включённый subagent возвращает адресную ошибку, как остальные неисправные расширения.
  - [ ] Не запускать daemon автоматически и не считать файл сокета доказательством работоспособности.
  - [ ] Оставить describe/context только читающими; `sessions compact` не создаёт задачи и не регистрирует изменяющее состояние обслуживания.
  - [ ] Передавать в инструкции модели назначение инструментов, правила ожидания, общий workspace и неизвестный исход операций.
  - [ ] При отключении subagent не обращаться к сокету и не менять обычный набор инструментов Horizon.

- [ ] Реализовать операции делегирования.
  - [ ] Реализовать spawn с быстрым подтверждением принятой задачи и новой сессией; исполнение продолжается независимо от процесса клиента инструмента.
  - [ ] Передавать home/workspace/access/session/turn/call из host Request, а не из управляемых моделью полей.
  - [ ] Использовать host operation_id для дедупликации spawn/send/cancel; потеря ответа не создаёт новую операцию при восстановлении её состояния.
  - [ ] Реализовать list/read с ограниченным объёмом результата и проверкой принадлежности родителю на стороне демона.
  - [ ] Реализовать send как очередь сообщения следующего хода ребёнка, без прерывания работающего хода; для завершённого ребёнка сообщение запускает следующий ход той же сессии.
  - [ ] Реализовать wait с ограничением до 30 секунд внутри текущего 60-секундного tool timeout, возвратом актуальных состояний и курсора при истечении ожидания.
  - [ ] Реализовать cancel с явным выбором одного ребёнка или его дерева; повторная отмена уже завершённой задачи не запускает новый ход.
  - [ ] Сохранять детей после завершения родительского хода; при следующем ходе той же сессии list/read позволяют получить результаты.

- [ ] Сохранить режимы доступа и журналирование.
  - [ ] Объявить list/read/wait эффектом read; операции spawn/send/cancel — write_home, поскольку они изменяют очередь и управление задачами.
  - [ ] Запретить изменяющие операции в read даже для ребёнка с read: запуск всё равно создаёт сессию и запись очереди.
  - [ ] Ограничить child access режимом родителя; daemon применяет ограничение повторно и передаёт наследуемый режим процессу Horizon.
  - [ ] Проверить запрет обхода ограничений через send к ранее созданному ребёнку с более широкими правами: новый ход не получает права выше текущего отправителя.
  - [ ] Использовать обычный журнал pending/known/unknown; разрыв сокета после отправки изменяющего запроса не выдавать за гарантированный отказ до запуска.
  - [ ] Возвращать operation ID и способ проверки результата при неизвестном исходе; не выполнять автоматический повтор под новым ID.
  - [ ] Проверить лимиты глубины и количества детей на сервере, включая рекурсивное использование subagent дочерними Horizon.
  - [ ] Документировать доверенный локальный протокол без обещания ОС-песочницы: процесс с правами пользователя может обращаться к его файлам и сокету.

- [ ] Подготовить поставку и пользовательскую документацию.
  - [ ] Добавить plugin.json и сборку subagent в Makefile и каталог manager.
  - [ ] Сохранить явное включение `agent_plugins`; установка бинарника не включает делегирование и не запускает daemon.
  - [ ] Добавить CLI-справку с диагностикой подключения без требования ключа провайдера для metadata/help.
  - [ ] Описать в README.md и docs/PLUGINS.md установку daemon/subagent, запуск демона и включение инструментов.
  - [ ] Обновить docs/TOOLS.md и docs/ARCHITECTURE.md с границами ответственности и примерами делегирования.

- [ ] Проверить весь путь от модели до дочернего процесса.
  - [ ] Проверить схемы, эффекты, namespace, отсутствие плагина, недоступный сокет и несовместимый handshake.
  - [ ] Проверить spawn → wait/read → send → следующий ход → cancel на временном home с тестовым провайдером.
  - [ ] Проверить обычный родительский Horizon вне daemon и родителя, запущенного самим daemon.
  - [ ] Проверить восстановление потерянного ответа без второго ребёнка и корректный unknown после сбоя демона.
  - [ ] Проверить access read/write/full, чужие task ID, более привилегированного ребёнка и предел рекурсии.
  - [ ] Проверить прогресс ребёнка при ожидающем родителе и несколько одновременно ожидающих родителей на пределе очереди.
  - [ ] Проверить отсутствие запуска детей при compact, пустом вводе и справке.
  - [ ] Выполнить gofmt, сборку ядра и обоих новых плагинов, `go test ./...`, `go vet ./...`, `go test -race ./...` и `git diff --check` без реального API.
