# Диагностика кеша промпта

`model_request_completed` в JSONL Horizon и в локальном журнале Telegram
показывает `input_tokens`, `output_tokens` и `cached_tokens` для каждого
обращения, когда провайдер возвращает эти значения. `usage_available: false`
означает отсутствие числового расхода; `cached_tokens: 0` означает измеренный
ноль. Сопоставляйте `attempt` и `phase` с событиями одного хода.

## Контрольная проверка 12 октября 2026 года

На локальном ключе OpenRouter, модели `openai/gpt-6-luna` и маршруте OpenAI
выполнены короткие запросы примерно по 1,5 тысячи входных токенов. Каждый
вариант получил новый префикс, чтобы исключить кеш от предыдущей пробы.

| Продолжение после общего префикса | Кешированные токены по четырём запросам |
| --- | --- |
| Меняющееся второе сообщение пользователя | 0, 0, 0, ~1532 при точном повторе |
| То же с `x-session-id` | 0, 0, 0, ~1533 при точном повторе |
| То же с явной точкой кеширования на первом сообщении | 0, ~1523, ~1523, ~1534 |
| Меняющееся сообщение ассистента, как продолжение хода | 0, ~1523, ~1523, ~1523 |

В журнале OpenRouter запрос без попадания стоил около $0.000192, с
попаданием около $0.000018–0.000019. Эксперимент с ответом ассистента
показал, что текущий формат запроса уже позволяет кешировать продолжение
хода. Явная точка помогала лишь в пробе с новым пользовательским сообщением
внутри каждого запроса. Закрепление маршрута через `x-session-id` само по
себе не помогло. Поэтому Horizon не добавляет эти параметры автоматически:
их польза для реального цикла инструментов не подтверждена.

Локальный тест не объясняет нулевой cache hit в исходном длинном ходе на
другом ключе и машине. Для него нужны числовые события конкретных обращений
и детали маршрута из OpenRouter, особенно при росте окна, сжатии или смене
провайдера. Общий процент за час смешивает разные запросы и не позволяет
приписать перерасход одной причине.

Повторить короткий платный эксперимент на настроенном провайдере можно
отдельно от пользовательской сессии:

```sh
HORIZON_CACHE_CHECK=1 go test ./internal/responses -run TestConfiguredPromptCacheRouting -v -count=1
```

Он не печатает ключ и текст запроса. Значения кеша могут отличаться из-за
маршрута и состояния кеша провайдера; это измерение, а не обязательный
регрессионный тест.
