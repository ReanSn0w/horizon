# Подключаемые команды

Horizon обнаруживает плагины только среди непосредственных исполняемых файлов
`<home>/plugins/horizon-<имя>`; symlink на исполняемый файл допустим. Имя
соответствует `[a-z][a-z0-9-]*`. Home выбирается через `--home`, затем
`HORIZON_HOME`, затем стандартный `~/.horizon`. `PATH`, текущий каталог и
родительские каталоги не сканируются. Имена встроенных команд и их алиасов
зарезервированы; плагин не заменяет встроенную команду или подкоманду.

Перед запуском Horizon вызывает файл с единственным аргументом
`horizon-plugin-metadata`, закрытым stdin и окружением, описанным ниже. В stdout
должен быть ровно один JSON-объект:

```json
{"protocol_version":1,"version":"1.0.0","description":"Example command"}
```

`version` и `description` — непустые строки. Дополнительные поля разрешены.
Таймаут — 2 секунды; stdout и stderr ограничены 64 КиБ каждый. Ошибка процесса,
невалидный JSON, лишний вывод и другая версия протокола делают плагин
недоступным. Корневая справка имеет общий бюджет ожидания 5 секунд и явно
помечает непроверенные кандидаты. Недоступные плагины выводятся в stderr;
встроенные команды при обычном запуске сторонние файлы не выполняют.

`horizon <имя> ...` удаляет имя команды и передаёт остальные аргументы буквально.
Плагин сам разбирает подкоманды, `--help` и `--`. Глобальный `--verbose` остаётся
диагностикой Horizon и не передаётся в argv плагина. Horizon запускает файл
напрямую, с текущим рабочим каталогом и потоками stdin/stdout/stderr.
Окружение наследуется, но `HORIZON_HOME` заменяется разрешённым home, а
`HORIZON_EXECUTABLE` — абсолютным путём запущенного Horizon. Ключ провайдера
из конфигурации не подгружается.

Обычный код выхода плагина передаётся без изменения; Ctrl+C даёт 130, другие
сигналы — `128 + номер сигнала`. Ошибки запуска Horizon дают 1, ошибки
аргументов и несовместимости протокола — 2. Коды встроенных команд прежние.
Обычный запуск требует существующего `<home>/config.yaml`, но не разбирает
настройки провайдера. Корневая справка и `horizon <имя> --help` не требуют
инициализированного home и не создают его силами Horizon.

## Настройки плагинов

Настройки установленных плагинов размещаются в общем `<home>/config.yaml`, под
необязательным верхнеуровневым ключом `plugins`. Ключ следующего уровня совпадает
с именем команды, например `plugins.decision`. Каждый плагин владеет схемой
только своей секции; поведение при её отсутствии определяет сам плагин.
Horizon не передаёт её содержимое через аргументы или окружение: плагин читает
выбранный `HORIZON_HOME/config.yaml` сам. Метаданные и справка плагина не должны
зависеть от содержимого этой секции.

```yaml
plugins:
  decision: {}
```

Пустая секция приведена только как пример расположения. У плагина `decision`
нет собственных параметров: URL, ключ и модель Jev остаются
в общей верхнеуровневой секции `decision`, которую использует и агент. Дублировать
их в `plugins.decision` не нужно. Строгий загрузчик принимает необязательный
`plugins` как отображение имён
плагинов в их настройки и сохраняет вложенные YAML-значения без общей схемы.
Остальные поля конфигурации по-прежнему проверяются строго.

Плагин [telegram](../plugins/telegram/README.md) использует `plugins.telegram`.
`telegram init` добавляет её без перезаписи существующих значений. Изменения
конфигурации выполняются через `config.UpdateDocument` под общей постоянной
блокировкой: изменения групп и `skills enable/disable` не теряют друг друга.
Telegram проверяет собственную схему строго и требует заполненные настройки
Telegram перед запуском.

Плагин исполняется с правами пользователя ОС, включая сеть и доступные файлы;
граница процесса не является песочницей. Поддерживаемые операции с сессиями
идут через CLI Horizon. Прямая запись во внутренние JSON-сессии не является
API; повторный вызов занятой сессии возвращает ошибку блокировки. При отмене
Horizon завершает управляемые процессы; потомки, самостоятельно отделившиеся
от группы, могут продолжить работу.
## Расширения агента (версия 1)

CLI-плагин может дополнительно объявить `agent_protocol_version: 1` в metadata.
Хост подключает только установленные исполняемые файлы, явно перечисленные в
`agent_plugins: [memory]` в config.yaml; по умолчанию список пуст. Порядок списка
определяет порядок контекста. Настройки по-прежнему принадлежат `plugins.<name>`.
Старые плагины не получают новых служебных вызовов.

Расширение — доверенный код с правами пользователя ОС. Декларации эффектов
не являются песочницей. Инструменты расширений запускаются напрямую, без Jev;
проверка Jev для `shell_exec` остаётся прежней.

Служебные команды получают ровно один JSON-объект через stdin, возвращают ровно
один через stdout, диагностику пишут в stderr. Ответы имеют форму
`{"ok":true,"data":...}` или `{"ok":false,"error":{"code":"...","message":"..."}}`.
Запрос содержит `home`, `workspace`, `workspace_id`, эффективный `access` и
`operation_id`. Для tool также передаются `session_id`, `turn_id`, `call_id`,
локальное `tool` и объект `arguments`. Пути выбирает хост, а не модель.

- `horizon-plugin-agent-describe`: data содержит `instructions`, `tools` и
  необязательный `maintain_effect`. Каждый tool содержит `name`, `description`,
  `parameters` (строгая JSON Schema) и `effect`.
- `horizon-plugin-agent-context`: data — массив объектов `source`, `text`.
  Только чтение; запись и запросы внешнего API запрещены контрактом.
- `horizon-plugin-agent-maintain`: необязательное обслуживание перед снимком
  непустого resume. Ошибка даёт предупреждение; затем читается прежний контекст.
  При sessions compact обслуживание не запускается.
- `horizon-plugin-agent-tool`: data — результат инструмента. Запись журналируется
  существующим механизмом pending/known/unknown до запуска и после результата.

Эффекты: `read`, `write_home`, `write_workspace`, `unrestricted`. В access read
разрешён только read; write разрешает также обе ограниченные записи; full — все.
Запрещённая операция отклоняется до запуска. Обслуживание подчиняется тем же
правилам. Эффект указывается также для инструментов, которые не разрешены в
текущем режиме: модель получает явный отказ, а не скрытую запись.

Имена API: `<plugin>__<tool>`, только ASCII-буквы, цифры, `_`, `-`, не более
64 символов. Пустые имена и коллизии отвергаются до хода. Поддерживаемая схема:
object (все свойства required, additionalProperties false), string, number,
integer, boolean, null, enum, array с items; nullable type допускает массив типов.
Неподдерживаемые ключи отвергаются, вложенность ограничена 16 уровнями.

Describe/context имеют таймаут 2 секунды и предел stdout/stderr 64 КиБ каждый.
Tool/maintain — 60 секунд и те же пределы. Общий бюджет подготовки — 90 секунд.
Суммарный контекст расширений ограничен 64 КиБ, описания и схемы входят в предел
describe. Отмена завершает группу процессов SIGTERM, затем SIGKILL; отделившиеся
потомки остаются за пределами этой гарантии. Диагностика tool сохраняется в
артефактах. Никакая служебная операция автоматически не повторяется.

Отказ до запуска имеет код `access_denied`/`plugin_start_failed`; нарушение
протокола, таймаут или отмена после запуска дают `plugin_outcome_unknown`.
При таком результате нельзя автоматически повторять запись: сначала прочитайте
состояние или используйте документированный механизм дедупликации плагина.
