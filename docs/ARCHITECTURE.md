# Границы Horizon

Статус: CLI и его пакеты перенесены в `harness/`; выделение agent предстоит.
Horizon остаётся одним репозиторием с двумя частями: `harness/` и `agent/`.
Эти имена обозначают каталоги и архитектурные роли. Бинарник harness сохраняет
имя `horizon`; имя бинарника agent и его поставка будут определены отдельно.

## Harness

Harness — самостоятельная CLI-утилита. Пользователь может установить и
использовать только её из терминала, скриптов или по SSH. Agent для этого
не требуется. Один запуск выполнения хода принимает запрос, выполняет цикл
модели и инструментов, возвращает результат и завершается.

Harness отвечает за:

- инструкции, контекст, загрузку навыков и взаимодействие с моделью;
- инструменты, режимы доступа, лимиты и отмену выполнения;
- сессии, журнал вызовов, артефакты, блокировки и восстановление после сбоя;
- сжатие контекста внутри хода и явные CLI-операции сжатия и обслуживания;
- встроенные memory и decision;
- MCP-клиент, конфигурацию серверов и подключение их инструментов;
- подключение внешних плагинов.

Memory и decision становятся штатными возможностями, а не отдельно
устанавливаемыми плагинами. Наличие в поставке не обязывает включать возможность
или настраивать её провайдера для каждого запуска. Детали конфигурации и перехода
с текущей установки определяются при реализации.

Состояние сохраняется между запусками: самостоятельность CLI не означает
отказ от сессий и памяти. Логика хранения и изменения этих данных принадлежит
harness.

Browser остаётся опциональным плагином и не устанавливается по умолчанию.
Пользователь может использовать доступный локальный Chrome в headless-режиме
через shell и навыки либо отдельно установить браузерный плагин, например
для работы на сервере. Автоматическое обнаружение Chrome и новый встроенный
браузерный инструмент этим решением не вводятся.

## Agent

Agent — отдельный долгоживущий процесс, который запускает CLI harness
в ходе своей работы. Он отвечает за:

- шлюзы, включая Telegram, приём сообщений и доставку ответов;
- маршрутизацию запросов по workspace и сессиям;
- очереди, расписания и управление дочерними запусками;
- автоматическое сжатие между ходами и фоновое обслуживание через CLI harness;
- собственное служебное состояние: очереди, связи чатов с сессиями и расписания.

Agent не реализует второй цикл модели и инструментов и не изменяет напрямую
внутреннее хранилище сессий или памяти harness. Он выбирает, когда выполнить
операцию, а harness владеет её исполнением. Шлюз отвечает за свой транспорт;
общие очереди и обслуживание не должны зависеть от Telegram.

## Граница процессов

Пользователь или скрипт запускает harness напрямую. Agent использует тот же
исполняемый CLI через аргументы, ввод, структурированные события, результат
и код завершения. Вызов внутреннего Go-пакета агентского цикла не заменяет
эту границу. Harness не зависит от работающего agent.

Текущий `jsonl` — основа для будущего контракта взаимодействия. До переноса
нужно проверить его полноту для запуска, ошибок, отмены и обслуживания;
новый протокол этим документом не вводится.

## Плагины, MCP и навыки

Плагин — исполняемое расширение harness, которое добавляет в ход:

- инструкции и/или контекст;
- инструменты;
- либо обе возможности вместе.

Это две смысловые точки расширения хода. Инструкции использования и контекстные
данные различаются: внешние данные не получают приоритет системных инструкций.
Служебный жизненный цикл плагина определяется отдельно при пересмотре протокола;
он не является дополнительным способом вмешательства в ход.

Плагин может поставлять сопутствующие навыки. Их обнаружение и чтение используют
стандартный механизм навыков, без отдельного пути внедрения в ход. Набор,
содержащий только навыки, плагином не считается.

MCP — встроенный способ подключения внешних серверов к harness. Его инструменты
и инструменты плагинов должны проходить через общие механизмы регистрации,
валидации, исполнения и журналирования с учётом контракта доступа каждого
источника. MCP-сервер не обязан реализовывать собственный протокол плагинов Horizon.

## Размещение и постепенный переход

| Текущая часть | Целевая принадлежность |
| --- | --- |
| CLI, цикл модели, Responses API, сессии, инструменты, инструкции и навыки | `harness/` |
| `plugins/memory`, `plugins/decision`, `harness/decision` | Встроенные возможности `harness/` |
| `plugins/browser` | Опциональный плагин harness, без установки по умолчанию |
| `plugins/telegram` | Шлюз и управляющая логика в `agent/`, разделённые по ответственности |
| Будущая поддержка MCP и пересмотренный механизм плагинов | `harness/` |
| Установка, обновление и релизная инфраструктура | Поставка проекта; конкретное размещение определяется отдельно |

Текущий `harness/internal/agent` содержит цикл модели и относится к harness,
несмотря на совпадение имени с новым каталогом `agent/`.

CLI и его пакеты находятся в `harness/`; `agent/` пока содержит только README.
Корневой Go-модуль сохранён. Сборка CLI из корня: `go build -o /tmp/horizon-dev ./harness`.
Пользовательские команды, форматы данных и имя бинарника `horizon` сохранены. Поддержка MCP и встраивание memory и decision ещё не реализованы.
Документы `TOOLS.md`, `PLUGINS.md`, `DISTRIBUTION.md` описывают действующую
реализацию, пока соответствующая часть не перенесена.

Перенос выполняется отдельными изменениями с сохранением работоспособности
CLI и существующих данных. Вместе с каждой частью обновляются её тесты,
сборка и документация. На этом этапе используется один Go-модуль без миграции пользовательской
конфигурации. Дальнейшие изменения поставки требуют отдельных решений.

### Карта первого переноса

Сохраняется один корневой Go-модуль. Пакеты `buildinfo`, `config`, `decision`,
`distribution`, `plugins`, `responses`, `session` размещены в
`harness/<имя>`: они используются текущими плагинами и релизными командами.
Их транзитивные импорты не требуют открытия других пакетов harness.
Это совместимость исходников монорепозитория, а не публичный Go SDK.

Пакеты `agent`, `agenttool`, `bootstrap`, `cli`, `e2e`, `eventstream`,
`instructions` размещены в `harness/internal/`. Точка входа —
`harness/main.go`, пример конфигурации — `harness/config.example.yaml`.
Каталог `plugins/`, релизные команды `cmd/` и инфраструктура сборки остаются
в корне. Исходные build, test и vet перед переносом прошли на Go 1.26.7.

Telegram временно импортирует пакеты `harness/config`, `harness/decision`,
`harness/session` и `harness/buildinfo`. При выделении agent обращения к
внутреннему состоянию должны быть заменены CLI-операциями harness. Эти
временные импорты не являются контрактом будущего agent.
