# Исправление навигации Browser Use

Проверка 2026-10-05 воспроизвела отказ установленного плагина из коммита
`ec1f7e1` на сервере `agent`, с home по умолчанию и `action_timeout: 30s`.
Настройки и приватные CDP URL в отчёт не включены.

Browser Use возвращал `cdpUrl` со схемой HTTPS. `runCDP` передавал его напрямую
WebSocket-клиенту с `chromedp.NoModifyURL`. Подключение завершалось до навигации,
а исходная ошибка заменялась строкой `remote browser action failed`.
Стандартное `/json/version` на этом HTTPS endpoint вернуло WSS-адрес.

После исправления discovery `example.com` открывался и сохранял вкладку между
подключениями. Habr выявил дополнительный таймаут ожидания полной загрузки.
Навигация теперь ожидает `DOMContentLoaded` основного документа с совпадающим
loader ID. Контролируемый тест не отправляет `loadEventFired`, но возвращает
содержимое страницы: фоновые ресурсы больше не блокируют чтение DOM.

Реальный opt-in тест на `agent` подтвердил содержимое `example.com`, повторное
подключение к той же вкладке и переходы на Habr и Hacker News. Созданные
диагностические сессии остановлены через API; закрытие WebSocket само по себе
не считается очисткой. Обычные тесты не обращаются к реальному аккаунту.

Протокол Browser Use и остановка управляемой сессии:
[документация провайдера](https://browser-use.com/playwright).
Установка и диагностические сообщения описаны в
[README плагина](../plugins/browser/README.md).
