## Horizon v0.4.0

### Основные изменения

- Telegram принимает документы и фотографии, сохраняет их в workspace и передаёт агенту путь, метаданные и подпись. Изображения пока не передаются модели как визуальный вход.
- Новый инструмент `telegram__send_file` отправляет документы и фотографии. Outbox сохраняет снимок файла; неизвестный исход отправки не приводит к автоматическому повтору.
- Команды адаптеров доступны через плагин `agent` и отображаются в `horizon agent -h`; служебные команды supervisor сохраняют приоритет.
- Настройки расширений собраны в `extensions`; установщик регистрирует расширения при первой установке.
- Таймеры без явного workspace используют `<home>/workspace/<имя-файла-без-.md>`. Обновлён nap: постоянные заметки между запусками, создание навыков и других таймеров, удаление завершённых временных сессий.
- Обновление передаётся менеджеру, собранному из выбранной новой ревизии, до обновления остальных компонентов и конфигурации.

### Обновление

Остановите supervisor и активные ходы, обновите ядро и плагины из одной ревизии,
затем запустите supervisor снова. Для перехода со старого менеджера, который
отказывает из-за несовместимого шаблона конфигурации, используйте новый бинарник
`horizon-manager` из этого релиза и выполните `update --home /absolute/path/to/home`.

Существующие пользовательские инструкции и таймеры не перезаписываются;
обновлённый пример nap доступен в `examples/timers/nap.md`.
Старые текстовые журналы Telegram совместимы. После появления файловых отправок
возврат к версии без их поддержки не поддерживается.

### Проверки

Локально прошли сборка ядра и Telegram-плагинов, `go test ./...`,
`go vet ./...`, `go test -race ./...` и сквозные тесты с mock Telegram/Responses.
Реальные Telegram и провайдер в этих проверках не использовались.

Релизный workflow собирает `horizon-manager` для Linux и macOS, amd64 и arm64,
и публикует `SHA256SUMS`. Для установки из исходников нужны Git и Go версии,
указанной в `go.mod` выбранной ревизии.
