# Memory

Память агента, пользователя и workspace встроена в harness и хранится в
локальных JSON-файлах. Для неё не нужен отдельный бинарник или запись в
`extensions`.

## Настройка

Новая конфигурация явно включает память:

```yaml
memory:
  enabled: true
  threshold: 5
  interval: 24h
  model: chatting
  note_limit: 4096
  summary_limit: 16384
  context_limit: 16000
  api_timeout: 45s
  retry_interval: 5m
  max_pending_notes: 256
  max_pending_bytes: 262144
```

`enabled: false` исключает контекст, инструменты и автоматическое обслуживание
из агентского хода, но не удаляет данные и не запрещает явные CLI-команды.
Старые `plugins.memory` и `agent_plugins: [memory]` продолжают читаться для
совместимости. `horizon-manager install` атомарно переносит их в верхнеуровневую секцию,
сохраняя прежнее состояние включения, комментарии, права и symlink на файл.
Одновременное наличие новой и старой схемы считается конфликтом.

Размеры измеряются в UTF-8 байтах. Строгая схема отвергает неизвестные поля.
Threshold: 1–256; note_limit: 1–16384; summary_limit: 1–32768;
context_limit: 256–32000; max_pending_notes: 1–1024; max_pending_bytes: от
note_limit до 1048576. Интервалы положительные, api_timeout не больше 45 секунд,
а `model` должен называть профиль из `models`. URL и ключ для сжатия
памяти берутся из подключения `providers`, указанного в `provider` этого профиля.

## Уровни и агентский ход

Один home соответствует одному агенту и пользователю. Для независимых
пользователей нужны разные home. Workspace — нормализованный абсолютный cwd с
разрешением symlink; корень Git не ищется.

- `agent` — устойчивые рабочие выводы агента;
- `user` — подтверждённые сведения о пользователе и предпочтения;
- `workspace` — решения и особенности конкретной директории.

При включённой памяти модель получает `memory__add(scope,text)` и
`memory__read(scope)`. Воспоминания добавляются в снимок как данные с указанным
источником, а не как инструкции поверх текущей задачи или `AGENTS.md`. Блоки
идут в порядке agent, user, workspace. Ограничение контекста меняет только
представление, а не сохранённые данные. Добавленная заметка появляется в
контексте следующего хода; результат инструмента доступен уже в текущем.

В access `read` чтение разрешено, а add и обслуживание отклоняются до записи.
В `write` и `full` память обслуживается перед снимком и после add. Команда
`sessions compact` читает контекст без обслуживания памяти.

## CLI и сжатие

```sh
horizon memory add --scope user --text 'Предпочитает краткие ответы по-русски'
horizon memory add --scope workspace --text 'Сборка через make' --id project-build
horizon memory show --scope user
horizon memory compact --scope workspace
horizon memory clear --scope agent
horizon memory show --scope workspace --workspace /absolute/path
horizon memory watch --period 1m
```

Команды возвращают JSON в stdout; коды 0/1/2/130 означают
успех/ошибку/неверные аргументы или конфигурацию/отмену. Наследуемый
`HORIZON_INHERITED_ACCESS` имеет приоритет. Watch работает в foreground,
отменяется сигналом и не устанавливает фоновую службу.

Сжатие запускается при достижении threshold или истечении interval. Для него
отправляются только прежнее резюме и новые заметки обычным запросом Responses
с `store: false`, без инструментов и истории сессии. Это отдельный запрос к
диалоговому провайдеру; `/responses/compact` не используется. Ошибка сохраняет
прежнее резюме и pending notes, автоматический повтор ограничен
`retry_interval`. Успешный add остаётся успешным, даже если последующее сжатие
не удалось.

## Хранение и конкуренция

Файлы находятся в `<home>/memory/agent.json`, `user.json` и
`workspaces/<workspace-id>.json`. Формат версии 1, пути и идентификаторы не
менялись при переносе из плагина. Отсутствующий файл означает пустую память;
повреждение или несовместимая версия возвращают ошибку.

Записи атомарны, каталоги создаются с `0700`, файлы — с `0600`. Постоянный
`.json.lock` защищает состояние, `.json.compact.lock` — запрос сжатия. Во время
API-вызова состояние не заблокировано; после успеха удаляются только заметки из
входного снимка, поэтому конкурентный add остаётся pending. Clear меняет
generation и не позволяет старому результату сжатия восстановить данные.

Operation ID инструмента строится из session/turn/call, CLI генерирует его или
принимает `--id`. Повтор ID с тем же текстом идемпотентен, с другим текстом даёт
конфликт. Журнал хранит до 1024 ID и очищает записи старше 90 дней при следующем
add. При неизвестном исходе сначала проверяйте фактическое состояние, а не
повторяйте запись вслепую.
