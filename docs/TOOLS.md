# Инструменты Horizon

По умолчанию модель получает два последовательных function tools: `skill_read` и
`shell_exec`. Их схемы и исполнение находятся в `internal/agenttool`.
Используется `strict: true`, `additionalProperties: false` и
`parallel_tool_calls: false`. Результат возвращается в
`function_call_output` с исходным `call_id` и сохраняется в журнале сессии.

Успех имеет форму `{"ok":true,"data":{...}}`, ошибка —
`{"ok":false,"error":{"code":"...","message":"..."}}`. Ошибку инструмента
модель может исправить в следующем вызове. Неоднозначный результат исполнения
не следует автоматически повторять.

## `skill_read`

```json
{"name":"filesystem"}
```

`name` — точное имя навыка из каталога текущего хода. Результат содержит
`name`, `description`, `content` и абсолютный `base_dir`. Соседние ресурсы
навыка модель читает через `shell_exec`, используя `base_dir`. Новый или
включённый в текущем ходе навык станет доступен со следующего хода.

## `shell_exec`

```json
{"command":"rg --files","timeout_ms":10000,"max_output_chars":16000}
```

`command` — непустая строка для `/bin/sh -c`. `timeout_ms` — положительное
целое число или `null`; `max_output_chars` — число от 1000 до 100000 или
`null` (по умолчанию 16000). Поля обязательны, но допускают `null` там, где
указано. Каждый вызов начинается в исходном workspace: смена каталога и
переменные, объявленные внутри команды, не переносятся в следующий вызов.

В режимах `read` и `write` до запуска Horizon передаёт отдельной модели Jev текст
команды и пути workspace и `HORIZON_HOME`. Jev отвечает на два вопроса:
предполагается ли файловая запись и возможна ли запись вне этих путей. Режим
доступа, поручение пользователя и история диалога Jev не передаются. Horizon
сам применяет режим: `read` запрещает
вероятную запись, `write` — вероятную запись вне двух каталогов. При `full`
Horizon не вызывает Jev и не требует его настройки; команда запускается без
этой проверки. Сетевые и иные нефайловые эффекты оценкой Jev не
ограничены. При отказе возвращается `decision_denied`, при ошибке или неполном
ответе Jev — `decision_unavailable`; команда не запускается. Ключи и
известные секреты не отправляются Jev; вызов с ними отклоняется до запроса.
Успешный результат в `read` и `write` содержит `decision_id`; в `full` этого поля
нет. Оценка Jev семантическая, она не обеспечивает
изоляцию ОС: команда получает права и окружение процесса Horizon, включая
`PATH`, доступ к сети и `HORIZON_HOME`. Вложенному Horizon передаётся
эффективный режим в `HORIZON_INHERITED_ACCESS`.

CLI-команда установленного плагина вызывается через `shell_exec`, например
`horizon decision request.json`. Явно включённые расширения агента также
добавляют типизированные инструменты, описанные ниже.
Вложенный Horizon наследует выбранный home через `HORIZON_HOME`; подключаемая
команда получает его же. При отмене и таймауте shell-инструмент завершает
свою группу процессов; вложенный Horizon передаёт сигнал группе плагина. Потомки,
самостоятельно отделившиеся от группы, могут продолжить работу.

`data` содержит `cwd`, `exit_code`, `signal`, `stdout`, `stderr`,
`duration_ms`, `timed_out`, `truncated`, `stdout_path` и `stderr_path`.
Ненулевой `exit_code` — результат самой команды, а не ошибка инструмента.
Ограничение вывода относится только к контексту модели: полные потоки
сохраняются как артефакты сессии и могут быть прочитаны через `shell_exec`.
При отмене или таймауте Horizon останавливает управляемую группу процессов;
отделившиеся потомки могут продолжить работу.

### Управляемые долгие команды

Новый вызов `shell_exec` может указать `yield_time_ms`: положительное число от 1
до 30000. Значение `null` или отсутствие поля при исполнении старого вызова
сохраняет синхронный режим. В строгой схеме для новых вызовов поле обязательно
и допускает `null`. `yield_time_ms` ограничивает только первое ожидание;
`timeout_ms` по-прежнему ограничивает всё время жизни команды.

Если команда успела завершиться, возвращается прежний окончательный результат.
Иначе `data` содержит `status: "running"`, непрозрачный `process_id`, уже
полученные `stdout` и `stderr`, а также пути к полным артефактам. `ok: true`
означает, что запуск и получение статуса прошли успешно; оно не означает
успешный код выхода ещё работающей команды. В одном ходе допускается не более
четырёх одновременно работающих управляемых команд. ID действует только в этом
ходе и не является PID ОС.

`shell_wait` принимает `process_id` и `wait_ms` от 1 до 60000. Он возвращается
при завершении команды или истечении времени ожидания — что наступит раньше.
`shell_cancel` принимает `process_id` и завершает управляемую группу процессов.
Оба инструмента возвращают `status: "running"` либо `status: "completed"`,
окончательный `exit_code` или `signal`, `timed_out`, длительность и только новый
stdout/stderr с предыдущего успешного получения результата. Повторное ожидание
или отмена завершённого процесса возвращает тот же окончательный статус без
повторной выдачи текста. Сокращённый фрагмент отмечается `truncated`; полный
вывод остаётся в артефактах. Проверка состояния не запускает команду повторно.

Управляемые процессы принадлежат запущенному экземпляру Horizon и текущему
ходу. При попытке финального ответа с живыми процессами Horizon дожидается
их окончательного состояния и передаёт его модели перед итоговым ответом.
Отмена и истечение лимита хода завершают управляемые группы процессов.
Завершение самого Horizon не гарантирует остановку потомков; при восстановлении
сессии исход ранее работающей команды может быть неизвестен и не повторяется
автоматически. Этот механизм не переносит работу между запусками Horizon.

Файлы и каталоги модель тоже обрабатывает через `shell_exec`. Встроенный навык
`filesystem` содержит практические команды чтения и записи. Чтение, списки и
справка допустимы во всех режимах. `read` не допускает предполагаемую запись;
`write` допускает запись в workspace и `HORIZON_HOME`; `full` не ограничивает
путь. Ни один режим не ограничивает фактические права процесса на уровне ОС.

## Артефакты

Полные stdout/stderr хранятся в
`<home>/dialogs/<workspace-id>/<session-id>.artifacts/`. `sessions delete`
удаляет их вместе с файлом сессии после получения блокировки; форк копирует
артефакты, на которые ссылается переносимая история.

## Инструменты расширений агента

Явно включённые `agent_plugins` добавляют `<plugin>__<tool>` в тот же реестр
определений, валидации аргументов и исполнения. Вызовы сохраняются существующим
журналом pending/known/unknown; ошибка записи pending не позволяет запуск,
ошибка сохранения результата останавливает ход. Полная ограниченная диагностика
stderr сохраняется в артефакте plugin_stderr. Stdout служебной команды является
JSON-результатом инструмента и не печатается как финальный ответ.

Инструменты объявляют эффект: read, write_home, write_workspace, unrestricted.
Read разрешает только чтение; write — также запись в home/workspace; full — все.
Запрещённая операция получает access_denied до запуска процесса. Доверенный
плагин запускается напрямую, без Jev; shell_exec сохраняет прежнюю проверку.
Неизвестный исход после запуска имеет код plugin_outcome_unknown; автоматически
повторять такую запись нельзя. Удалённый инструмент возвращает unknown_tool.

Memory предоставляет:

```json
{"scope":"user","text":"Confirmed durable preference"}
```

для `memory__add` и `{"scope":"user"}` для `memory__read`. Scope: agent, user,
workspace; пути выбирает хост. Read возвращает ограниченные блоки source/text,
add — saved/id/duplicate и отдельный статус compaction. Ошибка сжатия после
успешного add не отменяет сохранённую заметку. Инструмента clear у модели нет.
[Подробности памяти](../plugins/memory/README.md),
[протокол расширений](PLUGINS.md).

Browser предоставляет `browser__navigate` с `{"url":"https://example.com"}`,
`browser__snapshot` с `{}`, `browser__click` с `snapshot_id` и `ref`,
`browser__type` с `snapshot_id`, `ref` и `text`. Все четыре инструмента имеют эффект
`unrestricted` и работают только в `full`. Результат страницы ограничен по длине;
`truncated` показывает усечение. Ссылки на элементы привязаны к последнему
`snapshot_id`. Для них браузер создаётся только после `navigate` и останавливается
хостом после хода. [Подробности](../plugins/browser/README.md).

Ошибки CDP браузерного плагина содержат этап выполнения и безопасную причину
(например, `remote browser connect failed: WebSocket handshake HTTP 403`).
Числовой код ошибки CDP не содержит произвольное сообщение сервера. Неизвестная
причина обозначается `unclassified error`; отсутствие снимка само по себе не
подтверждает, что сайт отказал в загрузке. CDP URL и ключи в диагностику не входят.

Навигация ждёт готовности DOM основного документа (`DOMContentLoaded`),
без ожидания загрузки всех сторонних ресурсов. Для содержимого, появившегося
позже, используйте новый `browser__snapshot`.
