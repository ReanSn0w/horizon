# Инструменты Horizon

Справочник семи инструментов модели. Схемы и обработчики находятся в `internal/agenttool`, загрузка навыков — в `internal/instructions`.

## Общие правила

- Все семь инструментов передаются модели в каждом запросе как function tools. Вызовы последовательные: `parallel_tool_calls: false`. Модель выбирает нужный инструмент сама.
- Используем `strict: true`, `additionalProperties: false`, все свойства аргументов перечислены в `required`. Для параметров с поведением по умолчанию разрешаем `null`; значение по умолчанию применяет Horizon.
- Обязательные строки вроде `path`, `name`, `command` не могут быть пустыми. Исключения: содержимое нового файла и `new_text` могут быть пустыми. Аргументы дополнительно проверяются исполнителем.
- Относительные пути разрешаются от директории `resume`, абсолютные используются напрямую. `~`, переменные окружения и glob в файловых инструментах не раскрываются; для shell действует синтаксис shell.
- Файловые инструменты работают с текстом UTF-8; чтение или редактирование неподдерживаемого бинарного содержимого возвращает `unsupported_encoding`. `shell_exec` позволяет работать с другими форматами.
- Ограничения порции вывода защищают размер контекста; они не ограничивают файловые права или сеть. Песочницы, списка разрешённых команд и дополнительного подтверждения вызовов нет.
- Результат сериализуется в JSON и передаётся в `function_call_output` с исходным `call_id`. В журнале сохраняются аргументы, результат и связь с turn.

Успех: `{"ok":true,"data":{...}}`. Ошибка: `{"ok":false,"error":{"code":"...","message":"...","details":{...}}}`. Состав `data` зависит от инструмента; `details` содержит полезные сведения для исправления вызова.

Общие ошибки: `invalid_arguments`, `not_found`, `already_exists`, `permission_denied`, `wrong_type`, `unsupported_encoding`, `io_error`. Ошибка инструмента доступна модели для исправления; сама по себе она не завершает turn. При отмене пользователем цикл останавливается и новые вызовы модели не выполняются. Изменяющие инструменты автоматически не повторяются после неоднозначной ошибки записи.

## file_create

Создать новый текстовый файл и все отсутствующие родительские директории.

```json
{"path":"src/example.go","content":"package main\n"}
```

- `path: string`, `content: string`.
- Существующий файл не перезаписывается: `already_exists`. Существующая ссылка, включая битую, также считается существующим объектом.
- Права новых объектов определяются обычными правами создания ОС и umask пользователя. Не меняем права существующих родительских каталогов.
- Результат: `path` (абсолютный), `bytes_written`, `created_directories` (список).
- При сбое создания часть родительских директорий может остаться; частично созданный файл удаляется по возможности. Ошибка сообщает, что осталось; безусловный откат дерева не выполняется.

## file_read

Читать текст по строкам без добавления номеров строк в само содержимое.

```json
{"path":"main.go","start_line":1,"line_count":200}
```

- `path: string`; `start_line: integer|null` — с 1, `null` означает 1; `line_count: integer|null` — 1–2000, `null` означает 200.
- Результат: `path`, `content` (точный текст с исходными переводами строк), `start_line`, `end_line`, `next_line` (номер продолжения или `null`), `eof`.
- Пустой файл или начало за EOF возвращает пустой текст, `end_line: null`, `next_line: null`, `eof: true`.
- Порция ограничена также 64 КиБ UTF-8; возвращаем только целые строки. Если первая запрошенная строка сама длиннее лимита, возвращаем `line_too_long` с номером строки и её размером. Для такого содержимого модель может использовать `shell_exec` с явным выбором фрагмента.
- Так модель может копировать `content` в `old_text` без удаления декоративных номеров строк. `next_line` позволяет последовательно дочитать файл.

## file_update

Заменить ровно один точный фрагмент существующего файла.

```json
{"path":"main.go","old_text":"port := 8080","new_text":"port := 9090"}
```

- Все три аргумента — строки. `old_text` непустой; оба фрагмента могут быть многострочными.
- Ноль совпадений: `text_not_found`; больше одного: `ambiguous_match`. В этих случаях файл не изменяется. Не выполняем приблизительное сопоставление, нормализацию пробелов или замену всех совпадений.
- `new_text: ""` удаляет фрагмент. Для вставки `old_text` содержит соседний текст, а `new_text` — тот же текст с добавлением.
- Результат: `path`, `replacements: 1`, `changed`, `bytes_before`, `bytes_after`. При равных фрагментах после проверки единственности возвращается `changed: false`.
- Остальное содержимое и права файла сохраняются. Если внешний процесс меняет файл одновременно, инструмент не обещает транзакцию с ним; блокировка истории чата не блокирует файлы проекта.

## dir_list

Перечислить непосредственное содержимое директории, включая скрытые элементы.

```json
{"path":".","offset":0,"limit":200}
```

- `path: string`; `offset: integer|null` — с 0, `null` означает 0; `limit: integer|null` — 1–1000, `null` означает 200.
- Сортировка по имени, с фиксированным порядком без зависимости от локали; обход нерекурсивный. Для подкаталога модель вызывает инструмент снова.
- Результат: `path`, `entries`, `next_offset` (или `null`). Элемент: `name`, `type` (`file`, `directory`, `symlink`, `other`), `size_bytes` для обычного файла или `null`, `target` для ссылки или `null`.
- Ссылки показываются отдельными элементами, автоматически не обходятся. Если каталог меняется между страницами, список не является снимком: модель может начать перечисление заново.

## dir_delete

Удалить файл, символическую ссылку или директорию.

```json
{"path":"build","recursive":true}
```

- `path: string`, `recursive: boolean` — обязательное явное значение.
- Файл или ссылка удаляется при любом значении `recursive`; ссылка удаляется сама, её целевой объект не удаляется.
- Пустая директория удаляется при `recursive: false`. Непустая требует `recursive: true`, иначе `directory_not_empty`.
- При рекурсивном обходе ссылки внутри дерева не обходятся. Отсутствующий путь считается успешным отсутствием: `deleted: false`.
- Результат: `path`, `deleted`, `type` (или `null`, если объекта не было).
- Рекурсивное удаление не транзакционно: при ошибке часть дерева может быть удалена. Возвращаем `partial_delete` с путём сбоя и описанием, если операция успела изменить дерево.

## skill_read

Прочитать основной текст навыка по имени из постоянно доступного модели каталога.

```json
{"name":"review"}
```

- `name: string`, точное имя из каталога. Путь вместо имени не принимается.
- Результат: `name`, `description`, `content` (полный Markdown после YAML-заголовка), `base_dir` (абсолютная директория навыка).
- Основной текст не обрезается молча. Ресурсы рядом автоматически не загружаются: модель может вызвать `file_read` или `shell_exec` с путём от `base_dir`.
- Ошибки инструмента: `skill_not_found`, `invalid_skill`. Некорректный YAML-заголовок или повторяющееся имя навыка останавливают сборку каталога до начала хода. Чтение не исполняет скрипты.

## shell_exec

Выполнить одну shell-команду и вернуть результат после завершения.

```json
{"command":"go test ./...","timeout_ms":120000,"max_output_chars":16000}
```

- `command: string`; `timeout_ms: integer|null` — положительный таймаут или `null` без таймаута; `max_output_chars: integer|null` — 1000–100000, `null` означает 16000.
- Используем `/bin/sh -c`, без интерактивного или login-режима; окружение наследуется от Horizon. Рабочая директория каждого запуска — исходный workspace. Стандартный ввод закрыт, stdin интерактивно не запрашивается, PTY нет.
- Каждая команда запускается в отдельном процессе; `cd` и `export` не переносятся в следующий вызов. Для нужного интерпретатора модель может явно вызвать, например, `bash -c '...'`.
- stdout и stderr читаются одновременно, чтобы заполнение одного канала не блокировало процесс.
- Результат: `cwd`, `exit_code` (или `null` при сигнале), `signal` (или `null`), `stdout`, `stderr`, `duration_ms`, `timed_out`, `truncated`. Ненулевой код команды остаётся в результате `ok: true`: инструмент выполнил запуск, а результат команды оценивает модель. Ошибка самого запуска — `ok: false` и `process_start_failed`.
- Бюджет вывода общий для stdout и stderr в Unicode-символах; при превышении сохраняем начало и конец, отмечаем пропуск. Полные потоки сохраняются вне контекста в служебных логах сессии; результат содержит `stdout_path` и `stderr_path` (абсолютные пути). Их можно прочитать через `file_read`, не повторяя команду ради потерянного вывода. Невалидные UTF-8 байты в JSON-представлении заменяются, исходные байты сохраняются в логах.
- По таймауту и Ctrl+C завершаем группу процессов: сначала SIGTERM, через 2 секунды оставшимся процессам группы SIGKILL. Обработчик держит блокировку сессии до остановки управляемых процессов и сохранения результата. Явно отделившиеся от группы процессы требуют отдельного управления средствами ОС; без изоляции нельзя обещать остановку любого демонизированного потомка.
- Сетевых ограничений и фильтра команд нет. Для долговременных сервисов используем средства ОС; собственных фоновых job ID и дополнительного инструмента ожидания нет.

## Логи инструментов

Полные stdout/stderr хранятся в `<home>/dialogs/<workspace-hash>/<session-id>.artifacts/`; имена файлов формируются Horizon из ID вызова. Это дополнение к основному JSON-файлу сессии.

`sessions delete` удаляет основной файл и каталог его артефактов после получения блокировки сессии; отдельный постоянный файл блокировки сохраняется. Форк копирует артефакты, на которые ссылается история до последнего успешного turn включительно, в том числе артефакты предшествующих неудачных попыток, и обновляет служебные ссылки; исходная сессия может быть удалена независимо. Если успешных turns нет, форк пустой и артефакты не копируются.
