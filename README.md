# Horizon

Консольный агент на Go для работы с репозиториями через Responses API.
Читает и изменяет файлы, выполняет shell-команды и сохраняет историю локально.
Один запуск — один ход; следующий запуск продолжает последнюю сессию
текущего каталога.

## Быстрый старт

Нужны macOS или Linux, Go версии из [go.mod](go.mod) или новее и провайдер
с поддержкой Responses API и сжатия контекста.

Из корня репозитория установите бинарник в каталог из вашего `PATH`:

```sh
go install .
```

Go устанавливает его в `GOBIN`, а если переменная не задана — в `$(go env GOPATH)/bin`.
Добавьте этот каталог в `PATH`. Для локальной сборки: `go build -o horizon .`.

Перейдите в проект, с которым хотите работать, и запустите:

```sh
horizon
```

При первом запуске Horizon создаст `~/.horizon/config.yaml` и предложит его
заполнить. Укажите:

- `provider.url` — базовый URL API, например `https://api.openai.com/v1`;
- `provider.key` — ключ провайдера;
- `models.chatting.model` — идентификатор модели;
- `models.chatting.compact_threshold` — порог сжатия в токенах с запасом
  относительно окна контекста модели.

Все параметры показаны в [config.example.yaml](config.example.yaml).
Существующие настройки при запуске не перезаписываются.
Для другого каталога данных используйте `horizon --home /path/to/home`.

## Работа с агентом

```sh
horizon -m 'Посмотри проект и объясни его устройство'
horizon -m 'Теперь исправь найденную ошибку'
horizon < task.txt
```

Без сообщения откроется редактор: `Enter` отправляет текст, `Ctrl+J` добавляет
строку, `Ctrl+C` отменяет ввод. `Shift+Enter` тоже добавляет строку, если терминал
передаёт это сочетание.

`horizon` без подкоманды равнозначен `horizon resume`. Профиль модели можно
выбрать через `--model chatting`; доступные профили показывает `horizon models`.

Для скриптов доступны два режима:

```sh
horizon --mode plain -m 'Сделай обзор' > answer.txt
horizon --mode jsonl -m 'Проверь проект' > events.jsonl
```

В обычном режиме ответ идёт в stdout, статусы — в stderr. В `plain` успешный
запуск выводит только ответ; сообщение нужно передать через `-m` или stdin.
В `jsonl` stdout содержит события, по одному JSON-объекту на строку.
Флаг `--verbose` перед подкомандой включает подробности обычного вывода.

## Сессии

```sh
horizon sessions list
horizon sessions create
horizon resume --session SESSION_ID -m 'Продолжи задачу'
horizon sessions read --id SESSION_ID --turns 4
horizon sessions create --fork SESSION_ID
horizon sessions compact
horizon sessions delete --id SESSION_ID
```

История хранится в `~/.horizon/dialogs`. Каждый каталог проекта — отдельный
workspace: Horizon использует текущий путь и не ищет корень Git.
Сжатие уменьшает рабочий контекст, сохраняя историю. Форк создаёт независимую
копию сессии до последнего успешного хода.

## Инструкции и навыки

Horizon читает `AGENTS.md` из своего home и текущего каталога проекта.
Родительские каталоги не просматриваются.

Навыки находятся в `~/.horizon/skills/<имя>/SKILL.md`; каждый файл содержит
YAML-заголовок с `name` и `description`, затем инструкции. В комплект входит
`skill-creator` — можно попросить агента создать новый навык. Он станет
доступен со следующего хода.

Horizon работает с правами пользователя ОС, без встроенной песочницы.
Изменения файлов и последствия shell-команд автоматически не откатываются.

## Разработка

```sh
go test ./...
go vet ./...
go test -race ./...
```

Обычные тесты используют локальный тестовый сервер и не требуют ключа API.
Карта кода и правила изменений — в [AGENTS.md](AGENTS.md), описание инструментов —
в [docs/TOOLS.md](docs/TOOLS.md). Полная справка по командам: `horizon --help`.
